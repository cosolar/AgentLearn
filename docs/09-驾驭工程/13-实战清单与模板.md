## 二、可直接复制的模板

> 下面 6 个模板覆盖了 Harness 最常用的配置物料。直接改内容即可用。

### 2.1 `AGENTS.md` 模板（≤ 50 行）

```markdown
# AGENTS.md

## 项目概览
- 本项目是 XXX（一句话：是什么、给谁用）
- 技术栈：Python 3.12 · LangChain v1 · LangGraph 1.2
- 入口：`src/app/main.py`；核心编排：`src/app/graph/`

## 构建与测试命令
```bash
uv sync                        # 装依赖
uv run pytest -q               # 跑测试
uv run ruff check .            # 代码检查
uv run mypy src/               # 类型检查
```

## 代码风格
- ruff 格式化 + 检查，行宽 100
- 类型注解完整；公共函数必须有 docstring
- 异步优先：IO 一律 `async`，禁止在 async 函数里调用阻塞 IO

## 目录导航（地图而非手册）
- `src/app/api/`   路由层，只做参数校验与编排
- `src/app/graph/` LangGraph 图定义与节点
- `tests/`         与 src 结构镜像

## 硬性禁止
- ❌ 禁止修改 `tests/` 来"让测试通过"
- ❌ 禁止提交 `.env`、密钥、真实用户数据
- ❌ 禁止直接 push `main`，一律走 PR

## PR 惯例
- 分支：`feat/xxx`、`fix/xxx`；提交：Conventional Commits
```

> 💡 **只放"模型读代码也猜不出来"的东西**：构建命令、风格约定、禁止事项、PR 惯例。详见 [9.10](./10-标准与Skills.md)。

### 2.2 `SKILL.md` 模板

```markdown
---
name: <技能名，kebab-case>
description: <一句话说明做什么 + 何时触发。这是唯一常驻的部分，必须写得让 Agent 能判断"什么时候该用我">
---

# <技能标题>

## 何时使用
<列举触发场景，越具体越好>

## 步骤
1. <步骤一：具体动作 + 用哪个工具>
2. <步骤二>
3. <步骤三>

## 注意事项
- <什么情况下必须停下>
- <什么绝对不能做>
```

**目录结构**：

```text
<skills-dir>/<skill-name>/
├── SKILL.md
├── scripts/          # 可执行脚本
└── resources/        # 模板、数据、参考文档
```

### 2.3 Spec 模板（可执行规格）

```markdown
# spec: <功能名>

## 目标
<一句话说明这个功能解决什么问题>

## 行为规格
- <具体、可观测的行为，一条一句>
- <边界条件：超限、为空、并发时怎么办>

## 验收标准
1. <可程序化判定的条件一>
2. <可程序化判定的条件二>
3. <可程序化判定的条件三>
```

> 🎯 **关键**：验收标准要能**直接改写成测试**。一份规格同时是**前馈（照着做）**与**反馈（拿来验收）**。

### 2.4 Stop Hook 模板（确定性验证门）

```python
"""stop_gate.py —— Agent 想停，先过这一关。不通过就 block 并回注失败原因。"""
import subprocess
from dataclasses import dataclass


@dataclass
class Verdict:
    decision: str          # "allow" | "block" | "terminate"
    reason: str = ""


class StopGate:
    def __init__(self, commands: list[str], max_consecutive_blocks: int = 8):
        self.commands = commands                  # 如 ["uv run pytest -q", "uv run ruff check ."]
        self.max_blocks = max_consecutive_blocks  # ← 刹车：防止无限修复
        self.blocks = 0

    def check(self, workspace: str) -> Verdict:
        for cmd in self.commands:
            proc = subprocess.run(cmd, shell=True, cwd=workspace,
                                  capture_output=True, text=True, timeout=600)
            if proc.returncode != 0:
                self.blocks += 1
                if self.blocks >= self.max_blocks:
                    return Verdict("terminate",
                                   f"连续 {self.blocks} 次验证失败，强制终止，请人工介入")
                return Verdict("block",
                               f"`{cmd}` 失败，请修复后重试：\n{proc.stdout[-1500:]}")
        self.blocks = 0
        return Verdict("allow", "全部验证通过")
```

> ⚠️ **必须有刹车**：没有 `max_blocks`，"验证失败 → 修复 → 再失败"会变成无限循环。详见 [9.5](./05-验证循环.md)。

### 2.5 权限规则表模板（deny-first）

```python
"""permissions_rules.py —— deny 永远覆盖 allow，判定顺序不可颠倒。"""

# ① DENY：绝对禁止（优先级最高，命中即拒）
DENY_RULES = [
    (r"rm\s+-rf\s+/",              "禁止删除根目录"),
    (r"\bmkfs\b|\bdd\s+if=",       "禁止磁盘级操作"),
    (r"curl[^|]*\|\s*(bash|sh)",   "禁止管道执行远程脚本"),
    (r":\(\)\s*\{.*\};\s*:",       "禁止 fork 炸弹"),
    (r">\s*/etc/",                 "禁止篡改系统配置"),
    (r"(ruff|eslint|\.pre-commit)", "禁止修改 lint 配置来绕过检查"),
]

# ② ALLOW：低风险、高频，直接放行
READ_ONLY_TOOLS = frozenset({"read_file", "list_dir", "grep", "glob", "search_web"})
WRITE_TOOLS     = frozenset({"write_file", "edit_file"})

# ③ ASK：高风险，必须人工确认
ASK_RULES = [
    (r"git\s+push",  "推送会影响他人，必须确认"),
    (r"\bdeploy\b|kubectl\s+apply", "发布操作不可逆，必须确认"),
]
DANGER_TOOLS = frozenset({"run_shell"})

# 判定顺序：DENY → plan模式只读 → ALLOW → ASK
```

> 🔑 **核心**：**能靠代码保证的事，绝不要寄希望于模型的自觉。** 详见 [9.4](./04-权限护栏与沙箱.md)。

### 2.6 上下文预算监控模板

```python
"""context_budget.py —— 把"上下文是否在膨胀"变成可见指标。"""


class ContextBudgetMonitor:
    def __init__(self, soft_limit_chars: int = 120_000, warn_ratio: float = 0.8):
        self.soft_limit = soft_limit_chars
        self.warn_ratio = warn_ratio

    def observe(self, messages: list[dict], turn: int) -> dict:
        chars = sum(len(str(m.get("content", ""))) for m in messages)
        ratio = chars / self.soft_limit
        if ratio >= 1.0:
            level = "critical"
        elif ratio >= self.warn_ratio:
            level = "warn"
        else:
            level = "ok"
        # 生产环境应导出到 OTel / Langfuse，而不是 print
        return {"turn": turn, "chars": chars, "ratio": round(ratio, 3), "level": level}
```

## 四、Harness 成熟度自评表（L0–L4）

> 用法：逐级对照，**找到你当前所在级别**，然后只做"下一级"要求的事——不要跳级。

| 级别 | 名称 | 特征 | 下一步该做什么 |
|:----:|:-----|:-----|:---------------|
| **L0** | **裸模型** | 直接调 API，无循环、无工具 | 加一个编排循环 + 工具注册表（[9.2](./02-十二大模块解剖.md)） |
| **L1** | **能跑的 Demo** | 有循环、有工具，但无预算、无权限、无验证 | 加三重预算 + deny-first 权限（[9.4](./04-权限护栏与沙箱.md)、[9.8](./08-构建最小可行Harness.md)） |
| **L2** | **可信的助手** | 有权限与验证门，任务完成率稳定；但崩溃后要重来 | 加状态持久化 + 上下文压缩（[9.3](./03-上下文工程与压缩.md)、[9.6](./06-子Agent编排与长时任务.md)） |
| **L3** | **生产级 Agent** | 可恢复、可观测、有评测与告警；能跑长任务 | 加子 Agent 编排 + 自建评测集 + CI 回归（[9.6](./06-子Agent编排与长时任务.md)、[9.11](./11-评测与可观测性.md)） |
| **L4** | **可托付的平台** | 跨工具可移植、有标准配置、可持续优化 | AGENTS.md / Skills / Spec + harness 自动优化（[9.10](./10-标准与Skills.md)、[9.11](./11-评测与可观测性.md)） |

**自评快速判断**：

```text
问自己 4 个问题：
  ① 崩溃后能否从检查点续跑？         否 → 你在 L2 以下
  ② Agent 说"完成了"，你是否需要人工复核？  需要 → 你在 L3 以下
  ③ 换工具（Claude Code → Cursor）配置会不会全丢？  会 → 你在 L4 以下
  ④ 能否用数据证明"这次改动让 Harness 更好了"？  不能 → 你在 L4 以下
```

## 五、从 MVH 到生产的加固路线图

> 与 [9.8 第十节](./08-构建最小可行Harness.md) 呼应，这里给出**按投入产出比排序**的完整路线。

```text
  MVH 骨架（9.8 的 mini-harness）
        │
        ▼
  ┌─────────────────────────────────────────────────────────┐
  │ Phase 1  验证循环   ← ROI 最高，先做                      │
  │  verify.py → Stop Hook + 对抗性子 Agent                  │
  │  收益：任务完成率 83% → 96%                              │
  ├─────────────────────────────────────────────────────────┤
  │ Phase 2  状态持久化                                       │
  │  RunState → LangGraph checkpointer / Postgres            │
  │  收益：崩溃后 token 成本降 30–50%                        │
  ├─────────────────────────────────────────────────────────┤
  │ Phase 3  可观测性                                         │
  │  trace.py → OTel GenAI + Langfuse/LangSmith              │
  │  收益：可定位、可优化、可告警                             │
  ├─────────────────────────────────────────────────────────┤
  │ Phase 4  人在回路                                         │
  │  permissions.py → 完整权限光谱 + 容器沙箱                 │
  │  收益：生产安全底线                                       │
  ├─────────────────────────────────────────────────────────┤
  │ Phase 5  上下文工程                                       │
  │  context.py → 五层压缩 + JIT 检索 + 子 Agent 委派         │
  │  收益：支撑长任务与大规模代码库                           │
  ├─────────────────────────────────────────────────────────┤

  └─────────────────────────────────────────────────────────┘

> ⏱️ **时间预期**：生产级 Harness **需要数月而非数天**。Manus 6 个月 + 5 次重写；LangChain 为 LangGraph 执行引擎迭代 4 种架构、耗时超一年。**从 MVH 起步，逐阶段加固，是唯一务实的路径。**

## 📝 课后练习

1. **清单自评**：拿你手头的 Agent 项目，逐项过一遍第一节的 Checklist，统计通过率；把未通过项按"投入产出比"排序，写出你接下来的三步改造计划。
2. **成熟度定位**：用第四节的 4 个问题自评你的项目处于 L0–L4 哪一级，并对照该级的"下一步该做什么"落地一件事。
3. **反模式排查**：从第三节的 20 条反模式中，找出你的项目**已经踩中**的 3 条，给出具体修复方案（要能落到某一行代码或某个配置文件）。
4. **模板落地**：为你当前项目写一份 ≤ 50 行的 `AGENTS.md`，并写一个 `StopGate`，让"测试不通过就不许结束"真正生效——然后故意让测试失败一次，验证它确实拦住了。
