# 2.4 记忆机制 —— 短期记忆、长期记忆与"记忆是 hint 不是事实"

> 📅 更新至 2026-10 · 技术栈基线见 [教程大纲](../教程大纲.md)

## 📖 导读

> **一句话结论**：LLM 天生无状态，"记忆"是**我们主动把历史与知识重新喂回去**；在 v1 中，短期记忆用 `checkpointer`（`InMemorySaver` 起步），长期记忆用 LangGraph 的 `store`——但务必记住：**记忆是 hint，不是事实**。

- **前置阅读**：[2.3 Agent 核心架构](./03-Agent核心架构.md)。
- **本章你将学到**：
  1. 记忆的三种分类（工作 / 短期 / 长期）；
  2. 短期记忆：消息列表 → `trim_messages` → **`InMemorySaver`** → 自动摘要；
  3. 长期记忆：向量库、**LangGraph `store`**、专用记忆框架；
  4. 为什么**"记忆是 hint 不是事实"**，以及工程上如何防范记忆污染；
  5. 一个可运行的带记忆对话 Agent。

> 🆕 **v1 变化**：旧的 `langchain.memory`（`ConversationBufferMemory` 等）已迁往 [`langchain-classic`](https://pypi.org/project/langchain-classic/)。本教程改用 **LangGraph `checkpointer` / `store`** + **v1 中间件**，这也是当前的生产级做法。

## 一、前置知识

| 概念 | 说明 |
|------|------|
| **LLM 的无状态性** | 每次调用独立，模型本身不保留任何对话 |
| **Context Window** | 一次能处理的最大 token 数（2026 主流模型约 128K–1M） |
| **Token 成本** | 按输入/输出 token 计费，历史越长越贵 |
| **消息类型** | `SystemMessage` / `HumanMessage` / `AIMessage` / `ToolMessage` |
| **Checkpointer** | 保存图状态（**会话级**记忆），如 `InMemorySaver` |
| **Store** | 跨会话的键值存储（**长期**记忆） |

## 二、为什么需要记忆？

```text
❌ 没有记忆：
用户：我叫小明
Agent：好的
用户：我刚才说了我叫什么？
Agent：我不记得了 ❌

✅ 有记忆：
用户：我叫小明
Agent：好的，小明
用户：我刚才说了我叫什么？
Agent：你叫小明 ✅
```

| 能力 | 说明 | 价值 |
|------|------|------|
| **上下文连贯** | 跟上多轮对话 | 自然的交互 |
| **用户画像** | 记住偏好、习惯 | 个性化服务 |
| **任务跟踪** | 记住任务进度 | 断点续执行 |
| **知识积累** | 跨会话记住结论 | 持续进化 |

## 三、记忆的分类体系

按"**存多久 + 存哪里**"分为三类：

| 类型 | 生命周期 | 典型载体 | 用途 |
|------|----------|----------|------|
| **工作记忆（Working）** | 单次任务内 | 图状态 / 变量 | 当前任务的中间结果 |
| **短期记忆（Short-term）** | 单个会话内 | 消息列表 + `checkpointer` | 多轮对话上下文 |
| **长期记忆（Long-term）** | 跨会话、长期 | 向量库 / KV `store` | 用户画像、经验沉淀 |

```
┌──────────────────────────────────────────────────────┐
│  长期记忆 (Store / 向量库 / Mem0 · Letta · Zep)        │  跨会话
├──────────────────────────────────────────────────────┤
│  短期记忆 (消息列表 + Checkpointer)                    │  单个会话
├──────────────────────────────────────────────────────┤
│  工作记忆 (当前图状态 / 中间变量)                       │  单次任务
└──────────────────────────────────────────────────────┘
```

## 四、短期记忆：会话内的上下文

### 4.1 最朴素：消息列表

LLM 无状态，"记忆"其实是**每次把历史重新传进去**：

```python
from langchain_core.messages import HumanMessage, SystemMessage
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-5.5", temperature=0.7)
messages = [SystemMessage(content="你是一个友好的助手。")]


def chat(user_input: str) -> str:
    messages.append(HumanMessage(content=user_input))
    reply = llm.invoke(messages)      # 每次都带上完整历史
    messages.append(reply)
    return reply.content
```

- **优点**：简单、100% 准确；
- **缺点**：对话越长 token 越多，最终撑爆上下文窗口。

### 4.2 控制长度：`trim_messages`

```python
from langchain_core.messages import trim_messages

# 只保留最近、且总量不超过 max_tokens 的消息
trimmed = trim_messages(
    messages,
    max_tokens=2000,
    strategy="last",        # 从最新的开始保留
    token_counter=llm,      # 用模型自带计数器精确计数
    include_system=True,    # 保留 SystemMessage
)
```

### 4.3 生产级：LangGraph Checkpointer

`trim_messages` 仍需自己管理列表。**LangGraph 的 `checkpointer` 能自动持久化每一步状态**，并支持断点恢复：

```python
from langchain.agents import create_agent
from langchain_core.messages import HumanMessage
from langgraph.checkpoint.memory import InMemorySaver   # 注意：v1 新路径

# 开发用内存版；生产可换 SqliteSaver / PostgresSaver
checkpointer = InMemorySaver()

agent = create_agent(
    model="gpt-5.5",
    tools=[],
    checkpointer=checkpointer,
)

# 用 thread_id 区分不同会话
config = {"configurable": {"thread_id": "user-001"}}

agent.invoke({"messages": [HumanMessage(content="我叫小明")]}, config)
result = agent.invoke({"messages": [HumanMessage(content="我叫什么？")]}, config)
print(result["messages"][-1].content)   # → 你叫小明
```

| 记忆载体 | 适用场景 | 持久化 |
|----------|----------|--------|
| `InMemorySaver` | 本地开发、单进程 | ❌ 重启即丢 |
| `SqliteSaver` | 单机、中小规模 | ✅ 文件 |
| `PostgresSaver` | 生产、多实例 | ✅ 数据库 |
| `AsyncPostgresSaver` | 异步高并发生产 | ✅ 数据库 |

> 📌 完整用法见 [4.2 状态管理与节点](../04-LangGraph进阶/02-状态管理与节点.md)。

### 4.4 自动摘要压缩：SummarizationMiddleware

历史过长时，与其粗暴截断，不如**让模型自动摘要**：

```python
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware

agent = create_agent(
    model="gpt-5.5",
    tools=[],
    middleware=[
        # 当上下文超过 4000 token 时，自动把历史压缩成摘要
        SummarizationMiddleware(trigger={"tokens": 4000}),
    ],
)
```

```
原始对话（1000 tokens）→ 摘要（100 tokens）
↓
下次：摘要 + 最新消息（150 tokens）
↓
再摘要 → 持续迭代，token 稳定在低位
```

## 五、长期记忆：跨会话的知识沉淀

### 5.1 向量记忆（语义召回）

把重要信息存入向量库，需要时按语义检索回来：

```python
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma
from langchain_core.documents import Document

vectorstore = Chroma(
    collection_name="long_term_memory",
    embedding_function=OpenAIEmbeddings(model="text-embedding-3-small"),
    persist_directory="./memory_db",
)

vectorstore.add_documents([
    Document(page_content="用户叫小明，北京人，喜欢 Python 和咖啡。")
])

# 语义召回：问"用户来自哪"也能命中
hits = vectorstore.similarity_search("用户的家乡在哪里？", k=2)
print(hits[0].page_content)
```

### 5.2 LangGraph Store（跨会话长期记忆）

`store` 是 LangGraph 提供的**跨线程（跨会话）**键值存储，天然适合用户画像：

```python
from langchain.agents import create_agent
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()

# 直接写入 / 读取（namespace 用于隔离不同用户）
store.put(("users", "u-001"), "profile", {"name": "小明", "city": "北京"})
item = store.get(("users", "u-001"), "profile")
print(item.value)   # {'name': '小明', 'city': '北京'}

# 语义搜索（需为 store 配置 embedding 索引，此处仅示意接口）
# hits = store.search(("users", "u-001"), query="用户喜欢什么", limit=3)

agent = create_agent(
    model="gpt-5.5",
    tools=[],
    store=store,        # 工具/中间件内可通过 runtime.store 访问
)
```

| 组件 | 作用域 | 适合 |
|------|--------|------|
| `checkpointer` | **会话内**（同一 `thread_id`） | 多轮对话上下文 |
| `store` | **跨会话**（按 namespace 共享） | 用户画像、长期偏好 |

> 💡 二者可组合使用：`checkpointer` 管"这次聊了什么"，`store` 管"这个人是谁"。

### 5.3 专用记忆框架（2026 生态）

当长期记忆需求变复杂（抽取、去重、遗忘、图谱化）时，可引入专门的记忆层：

| 框架 | 特点 | 适合 |
|------|------|------|
| **Mem0** | 开箱即用，自动抽取/更新记忆 | 通用个性化 Agent |
| **Letta**（原 MemGPT） | 把记忆当"操作系统"分页管理 | 长时自主 Agent |
| **Zep** | 时序知识图谱，专注对话记忆 | 客服/助手类 |
| **LangMem** | LangChain 官方记忆 SDK | LangChain 技术栈 |

### 5.4 模型原生记忆工具

2026 年，主流厂商开始提供**原生记忆能力**。例如 Anthropic 的 Claude 提供 memory tool，允许模型在客户端读写 `/memories` 目录，把"记忆"变成模型可直接操作的工具，而非纯靠提示词拼接。

## 六、记忆是 hint，不是事实（重点）

这是记忆系统最容易被忽视、却最容易出事的一条原则。

### 6.1 为什么记忆不可信？

**记忆本质上是"被检索回来的文本"，它是上下文里的一个提示（hint），不是权威事实。** 它可能：

| 风险 | 例子 |
|------|------|
| **过期** | 半年前记的"用户在上海"，其实已搬到北京 |
| **记错** | 模型抽取时把"我不喜欢辣"记成了"我喜欢辣" |
| **污染** | 多个用户共用一个 namespace，张冠李戴 |
| **冲突** | 旧记忆与新对话矛盾，模型却采信了旧的 |
| **被注入** | 恶意内容被写入长期记忆，后续反复影响决策 |

### 6.2 正确的心智模型

```
用户输入 ──┐
           ├──▶ 上下文（hint 集合）──▶ 模型 ──▶ 输出
记忆检索 ──┘        ↑
                    └── 只是"参考信息"，不是"绝对真理"
```

> ⚠️ **关键原则**：
> 1. **实时事实 > 记忆**：涉及金额、库存、订单状态等，**必须查权威数据源**，不能只信记忆；
> 2. **记忆要带元数据**：写入时记录 `时间戳 + 来源 + 置信度`，检索时优先近期、可信的；
> 3. **冲突时以显式输入为准**：用户当前说的，永远比历史记忆优先；
> 4. **可纠错、可遗忘**：提供删除/修正入口，尊重用户对记忆的控制权；
> 5. **敏感记忆要审批**：可用 `HumanInTheLoopMiddleware` 把关写入。

### 6.3 反例与正例

```python
# ❌ 只依赖记忆回答事实性问题
#    模型可能基于过期记忆，报出早已失效的地址/余额

# ✅ 记忆做"提示"，事实查"源头"
@tool
def get_order_status(order_id: str) -> str:
    """查询订单的实时状态（权威数据源）。"""
    return "订单 #12345：已发货"   # 实际项目查数据库


# 让 Agent 用记忆来"个性化表达"，用工具来"确认事实"
system_prompt = """你可以参考长期记忆来个性化回复，
但涉及订单、金额、库存等事实，必须先调用工具查询，不得凭记忆作答。"""
```

## 七、实战：构建带记忆的对话 Agent

```python
from langchain.agents import create_agent
from langchain_core.messages import HumanMessage
from langgraph.checkpoint.memory import InMemorySaver

checkpointer = InMemorySaver()

agent = create_agent(
    model="gpt-5.5",
    tools=[],
    system_prompt="你是一个友好的 AI 助手，记住用户说过的重要信息。",
    checkpointer=checkpointer,
)


def chat(session_id: str, text: str) -> str:
    config = {"configurable": {"thread_id": session_id}}
    result = agent.invoke({"messages": [HumanMessage(content=text)]}, config)
    return result["messages"][-1].content


print(chat("s1", "你好，我叫小明"))          # → 你好，小明！
print(chat("s1", "我喜欢喝美式咖啡"))        # → 记住了
print(chat("s1", "我叫什么？喜欢喝什么？"))  # → 你叫小明，喜欢美式咖啡
print(chat("s2", "我叫什么？"))              # → 新会话，不知道
```

> ✅ 同一个 `thread_id` = 同一个会话，跨调用自动保持记忆；不同 `thread_id` 互不干扰。

**记忆管理实践清单**：

1. **分层**：工作 / 短期 / 长期分开存储；
2. **裁剪**：始终用 `trim_messages` 控制上下文；
3. **摘要**：长对话用 `SummarizationMiddleware` 自动压缩；
4. **持久化**：生产把 `InMemorySaver` 换成 `PostgresSaver`；
5. **隔离**：按 `thread_id` / `user_id` / namespace 隔离，防止串记忆；
6. **可遗忘**：提供删除/过期机制；
7. **存疑**：把记忆当 hint，事实必须回源验证。

## 八、常见问题与排查

### ❌ 记忆丢失（重启后消失）

```python
# 原因：用了 InMemorySaver / InMemoryStore（内存态）
# 解决：生产换成持久化后端（需先装独立包 langgraph-checkpoint-postgres）
from langgraph.checkpoint.postgres import PostgresSaver

with PostgresSaver.from_conn_string("postgresql://...") as checkpointer:
    checkpointer.setup()
    agent = create_agent(model="gpt-5.5", tools=[], checkpointer=checkpointer)
```

> 📦 **持久化后端是独立发行包**：Postgres 用 `uv add langgraph-checkpoint-postgres`（提供 `langgraph.checkpoint.postgres` 与 `langgraph.store.postgres`），SQLite 用 `uv add langgraph-checkpoint-sqlite`。**不装会直接 `ModuleNotFoundError`**——`langgraph-checkpoint` 本身只含内存态与序列化。

### ❌ Token 超限（上下文溢出）

```python
# 裁剪 + 摘要双保险
trimmed = trim_messages(messages, max_tokens=3000, strategy="last")
# 并配置 SummarizationMiddleware(trigger={"tokens": 4000})
```

### ❌ 多用户串记忆

```python
# 原因：所有用户共用一个 thread_id / namespace
# 解决：按用户隔离
config = {"configurable": {"thread_id": f"user-{user_id}"}}
```

### ❌ 记忆污染（记错/记串）

- 写入前做**去重与冲突检测**；
- 给记忆加**时间戳与来源**，检索时优先近期；
- 敏感记忆引入**人工审核**（`HumanInTheLoopMiddleware`）。

## 本章小结

| 要点 | 说明 |
|------|------|
| **记忆的本质** | LLM 无状态，记忆靠"把历史重新喂回去" |
| **短期记忆** | 消息列表 + `checkpointer`（`InMemorySaver` 起步） |
| **上下文裁剪** | `trim_messages` 控制 token，避免溢出 |
| **摘要压缩** | `SummarizationMiddleware` 自动压缩长历史 |
| **长期记忆** | 向量库 / LangGraph `store` / Mem0 等框架 |
| **checkpointer vs store** | 前者管会话内，后者管跨会话 |
| **记忆是 hint** | 记忆只是参考信息，事实必须回源验证 |
| **隔离与持久化** | 按 thread_id/namespace 隔离，生产用数据库后端 |
