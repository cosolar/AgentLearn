# 4.3 条件路由与循环 —— 让工作流"活"起来

> 📅 更新至 2026-10 · 技术栈基线见 [知识库大纲](../知识库大纲.md)

## 📖 导读

> **顺序执行是线性的，条件路由和循环让工作流有了"判断力"和"耐力"。**

前面的例子中，节点都是固定顺序执行的（A→B→C）。但真实世界的流程充满**分支**（"如果 A 成立走这条路，否则走那条路"）和**循环**（"结果不够好就重试"）。本章讲透四件事：**条件边**、**循环**、**`Command`（节点内跳转）**、**`Send`（运行时动态分发）**，并给出生产级**类型化流式（typed streaming v2）**。

## 二、条件路由（Conditional Edge）

### 2.1 基本概念

条件路由就像铁路的道岔——根据状态决定下一步走哪条路。

```python
from typing import TypedDict, Literal
from langgraph.graph import StateGraph, START, END


class RouterState(TypedDict):
    input: str
    sentiment: str          # "positive", "negative", "neutral"
    result: str


# 路由函数：返回值必须是已注册的节点名（或 END）
def route_by_sentiment(
    state: RouterState,
) -> Literal["positive_handler", "negative_handler", "neutral_handler"]:
    sentiment = state["sentiment"]
    if sentiment == "positive":
        return "positive_handler"
    elif sentiment == "negative":
        return "negative_handler"
    else:
        return "neutral_handler"


def positive_handler(state: RouterState) -> dict:
    return {"result": f"👍 正面反馈处理: {state['input']}"}


def negative_handler(state: RouterState) -> dict:
    return {"result": f"👎 负面反馈处理，需要跟进: {state['input']}"}


def neutral_handler(state: RouterState) -> dict:
    return {"result": f"➖ 中性反馈: {state['input']}"}


# 构建带条件路由的图
builder = StateGraph(RouterState)
builder.add_node("analyze", lambda s: {"sentiment": "positive"})   # 模拟情感分析
builder.add_node("positive_handler", positive_handler)
builder.add_node("negative_handler", negative_handler)
builder.add_node("neutral_handler", neutral_handler)

builder.add_edge(START, "analyze")

# 条件边：从 analyze 节点出发，根据情感路由
builder.add_conditional_edges(
    "analyze",              # 从哪里出发
    route_by_sentiment,     # 路由函数
    {                       # 路径映射（函数返回值 → 目标节点）
        "positive_handler": "positive_handler",
        "negative_handler": "negative_handler",
        "neutral_handler": "neutral_handler",
    },
)

builder.add_edge("positive_handler", END)
builder.add_edge("negative_handler", END)
builder.add_edge("neutral_handler", END)

app = builder.compile()
print(app.invoke({"input": "体验很好", "sentiment": "", "result": ""})["result"])
```

> 💡 当路由函数**直接返回节点名**时，第三个参数也可以简写为节点名列表：`builder.add_conditional_edges("analyze", route_by_sentiment, ["positive_handler", "negative_handler", "neutral_handler"])`。

### 2.2 路由函数的三种写法

```python
from typing import TypedDict, Literal
from langgraph.graph import END


class S(TypedDict):
    value: int
    is_complete: bool


# 写法 1：返回节点名字符串（最常用）
def simple_router(state: S) -> str:
    return "positive_branch" if state["value"] > 0 else "negative_branch"


# 写法 2：返回 Literal 类型（类型安全，IDE 可补全）
def typed_router(state: S) -> Literal["branch_a", "branch_b", "branch_c"]:
    if state["value"] == 0:
        return "branch_a"
    elif state["value"] < 0:
        return "branch_b"
    else:
        return "branch_c"


# 写法 3：返回特殊值 END（直接结束）
def router_with_end(state: S) -> str:
    return END if state["is_complete"] else "continue_node"
```

### 2.3 常用的路由场景

```python
from typing import TypedDict


class TaskState(TypedDict):
    input: str
    task_type: str          # "qa", "search", "code", "translate"
    requires_tool: bool
    has_error: bool
    retry_count: int


# 场景 1：按任务类型路由
def route_by_task_type(state: TaskState) -> str:
    routing = {
        "qa": "qa_agent",
        "search": "search_agent",
        "code": "code_agent",
        "translate": "translate_agent",
    }
    return routing.get(state["task_type"], "default_agent")


# 场景 2：是否需要工具
def route_tool_needed(state: TaskState) -> str:
    return "tool_executor" if state["requires_tool"] else "direct_responder"


# 场景 3：错误 / 重试路由
def route_error(state: TaskState) -> str:
    if state["has_error"]:
        return "retry_node" if state["retry_count"] < 3 else "error_handler"
    return "success_handler"
```

## 三、循环（Loop）

### 3.1 基本循环

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END


class LoopState(TypedDict):
    counter: int
    max_count: int
    result: str


def worker_node(state: LoopState) -> dict:
    """工作节点"""
    new_counter = state["counter"] + 1
    print(f"  第 {new_counter}/{state['max_count']} 轮")
    return {"counter": new_counter}


def should_continue(state: LoopState) -> str:
    """判断是否继续循环"""
    return "end" if state["counter"] >= state["max_count"] else "continue"


builder = StateGraph(LoopState)
builder.add_node("worker", worker_node)
builder.add_edge(START, "worker")

# 条件边实现循环：worker → worker（继续）/ END（结束）
builder.add_conditional_edges(
    "worker",
    should_continue,
    {"continue": "worker", "end": END},
)

app = builder.compile()
result = app.invoke({"counter": 0, "max_count": 3, "result": ""})
print(f"完成！共执行 {result['counter']} 轮")
```

**输出**：

```text
  第 1/3 轮
  第 2/3 轮
  第 3/3 轮
完成！共执行 3 轮
```

> ⚠️ 循环必须**有终止条件**（`max_count`、`max_iterations` 或收敛判断），否则会无限执行直到触发 `recursion_limit`（默认 25）报错。

### 3.2 手写 ReAct 循环（理解 `create_agent` 的内核）

这是 LangGraph 最经典的应用——用图实现"思考 → 行动 → 观察"循环。

```python
"""手写 ReAct 循环：agent ⇄ tools"""
import os
from typing import TypedDict, Annotated, Literal

from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langchain_core.messages import AnyMessage, HumanMessage, ToolMessage
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages


class AgentState(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]
    max_iterations: int
    iteration_count: int


@tool
def search_web(query: str) -> str:
    """搜索互联网。"""
    return f"关于 '{query}' 的搜索结果..."


@tool
def calculate(expression: str) -> str:
    """数学计算，例如 '123 * 456'。"""
    return str(eval(expression))  # noqa: S307 —— 教学示例，生产请用安全求值


def get_llm():
    return ChatOpenAI(
        model=os.getenv("LLM_MODEL_NAME", "gpt-5.5"),
        api_key=os.getenv("LLM_API_KEY"),
        base_url=os.getenv("LLM_BASE_URL"),
        temperature=0,
    )


TOOLS = [search_web, calculate]
TOOL_MAP = {t.name: t for t in TOOLS}


# 节点 1：调用 LLM 思考
def call_model(state: AgentState) -> dict:
    llm_with_tools = get_llm().bind_tools(TOOLS)
    response = llm_with_tools.invoke(state["messages"])
    return {
        "messages": [response],
        "iteration_count": state["iteration_count"] + 1,
    }


# 节点 2：执行工具
def execute_tools(state: AgentState) -> dict:
    last = state["messages"][-1]
    tool_messages = []
    for call in last.tool_calls:
        result = TOOL_MAP[call["name"]].invoke(call["args"])
        tool_messages.append(
            ToolMessage(content=str(result), tool_call_id=call["id"])
        )
    return {"messages": tool_messages}


# 路由：是否继续循环
def should_continue(state: AgentState) -> Literal["tools", "__end__"]:
    last = state["messages"][-1]
    if state["iteration_count"] >= state["max_iterations"]:
        return "__end__"
    if not getattr(last, "tool_calls", None):
        return "__end__"
    return "tools"


builder = StateGraph(AgentState)
builder.add_node("agent", call_model)
builder.add_node("tools", execute_tools)

builder.add_edge(START, "agent")
builder.add_conditional_edges(
    "agent",
    should_continue,
    {"tools": "tools", "__end__": END},
)
builder.add_edge("tools", "agent")      # 工具执行完 → 回到思考

app = builder.compile()

result = app.invoke({
    "messages": [HumanMessage(content="计算 123 * 456，然后搜索 AI Agent 的信息")],
    "max_iterations": 5,
    "iteration_count": 0,
})

for msg in result["messages"]:
    if isinstance(msg, HumanMessage):
        print(f"👤 {msg.content}")
    elif getattr(msg, "content", "") and not getattr(msg, "tool_calls", None):
        print(f"🤖 {msg.content[:120]}")
    elif isinstance(msg, ToolMessage):
        print(f"🛠️  {msg.content[:120]}")
```

> 💡 **官方快捷方式**：LangGraph 预置了 `ToolNode`（工具执行节点）和 `tools_condition`（路由函数），可直接替换上面的 `execute_tools` 与 `should_continue`：
>
> ```python
> from langgraph.prebuilt import ToolNode, tools_condition
>
> builder.add_node("tools", ToolNode(TOOLS))
> builder.add_conditional_edges("agent", tools_condition)   # 自动路由到 "tools" 或 END
> ```
>
> 而 LangChain v1 的 `create_agent` 本质就是"把上面这张图封装好"，见 [3.4 构建聊天 Agent](../03-LangChain实战/04-构建聊天Agent.md)。
>
> 📦 **包说明**：`langgraph.prebuilt` 自 LangGraph 1.2 起由独立发行包 **`langgraph-prebuilt`** 提供（`langgraph` 的硬依赖，默认自动安装），**导入路径不变**。

## 四、`Command`：在节点内决定跳转

`Command` 让**节点自己**决定下一步去哪（而不用额外的条件边），常用于"边更新状态边跳转"。

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.types import Command


class ReviewState(TypedDict):
    draft: str
    score: int
    status: str
    revision_count: int
    max_revisions: int


def review_node(state: ReviewState) -> Command:
    """评估草稿，并直接决定下一步跳转"""
    score = min(10, len(state["draft"]) // 10)
    if score >= 7:
        return Command(goto=END, update={"score": score, "status": "approved"})
    if state["revision_count"] >= state["max_revisions"]:
        return Command(goto=END, update={"score": score, "status": "max_reached"})
    return Command(goto="revise", update={"score": score, "status": "revising"})


def revise_node(state: ReviewState) -> Command:
    """修改后回到评估"""
    return Command(
        goto="review",
        update={
            "draft": state["draft"] + "\n（已补充细节）",
            "revision_count": state["revision_count"] + 1,
        },
    )


builder = StateGraph(ReviewState)
builder.add_node("review", review_node)
builder.add_node("revise", revise_node)
builder.add_edge(START, "review")

app = builder.compile()
result = app.invoke({
    "draft": "初稿",
    "score": 0,
    "status": "",
    "revision_count": 0,
    "max_revisions": 3,
})
print(result["status"], result["revision_count"])
```

| 方式 | 谁决定跳转 | 适合 |
|------|-----------|------|
| `add_conditional_edges` | 独立的**路由函数** | 路由逻辑与节点逻辑分离 |
| `Command(goto=...)` | **节点自己** | 节点需要"边处理边决定去向" |
| `Command(goto=[Send(...), ...])` | 节点自己 | 需要动态分发到多个下游 |

## 五、`Send`：运行时动态分发（Map-Reduce）

`Send` 用于**运行时才确定下游数量**的场景：把一批任务分发给同一个节点并行处理，再用 reducer 汇总（map-reduce）。

```python
from typing import TypedDict, Annotated
import operator
from langgraph.graph import StateGraph, START, END
from langgraph.types import Send


class MapState(TypedDict):
    topics: list[str]                       # 待处理的主题列表
    current_topic: str                      # 单个 worker 的输入
    summaries: Annotated[list[str], operator.add]   # 汇总结果


def dispatch(state: MapState) -> list[Send]:
    """为每个主题生成一个 Send → 分发给 summarize 节点"""
    return [Send("summarize", {"current_topic": t}) for t in state["topics"]]


def summarize(state: MapState) -> dict:
    """worker：处理单个主题（会并行执行多次）"""
    return {"summaries": [f"《{state['current_topic']}》的摘要"]}


builder = StateGraph(MapState)
builder.add_node("dispatch", lambda s: {})      # 入口占位节点
builder.add_node("summarize", summarize)

builder.add_edge(START, "dispatch")
builder.add_conditional_edges("dispatch", dispatch, ["summarize"])
builder.add_edge("summarize", END)

app = builder.compile()
result = app.invoke({
    "topics": ["LangGraph", "RAG", "多 Agent"],
    "current_topic": "",
    "summaries": [],
})
print(result["summaries"])
# ['《LangGraph》的摘要', '《RAG》的摘要', '《多 Agent》的摘要']
```

> ⚠️ **要点**：
> 1. `Send(node, payload)` 的 `payload` 会作为**该次调用的输入**合并进状态，所以 `current_topic` 必须先在 `TypedDict` 中声明；
> 2. 多个 `summarize` 会**并行**执行，写回同一字段时必须用 reducer（这里是 `operator.add`）；
> 3. `Send` 也可以由 `Command(goto=[Send(...), Send(...)])` 在节点内发起。

## 六、类型化流式（typed streaming v2）

LangGraph v1.1 引入 `version="v2"`，把多路流统一成 **`StreamPart`**（含 `type` / `ns` / `data`），便于网关与前端稳定解析。

```python
# 同时订阅"节点更新"与"消息 token"两路流
for part in app.stream(
    {"messages": [HumanMessage(content="你好")], "max_iterations": 3, "iteration_count": 0},
    {"configurable": {"thread_id": "s1"}},
    stream_mode=["updates", "messages"],
    version="v2",
):
    if part["type"] == "messages":
        chunk, metadata = part["data"]          # (AIMessageChunk, metadata)
        if chunk.content:
            print(chunk.content, end="", flush=True)
    elif part["type"] == "updates":
        print(f"\n[节点更新] {part['data']}")
```

| `stream_mode` | 输出内容 | 典型用途 |
|---------------|----------|----------|
| `"values"` | 每一步的完整状态 | 调试、状态快照 |
| `"updates"` | 每个节点的增量更新 | 观察执行轨迹 |
| `"messages"` | `(token, metadata)` 逐 token | 打字机效果 |
| `"custom"` | 节点内 `get_stream_writer()` 写入的自定义事件 | 进度条、业务事件 |

> 💡 v2 下每个分片结构固定为 `{"type": ..., "ns": (...), "data": ...}`；`ns`（namespace）能区分事件来自主图还是某个子图，做多子图流式时非常关键（见 [4.4 子图](./04-子图.md)）。

## 七、综合示例：条件路由 + 循环

```python
from typing import TypedDict, Annotated, List
import operator
from langgraph.graph import StateGraph, START, END


class WorkflowState(TypedDict):
    input: str
    stage: str                                        # 当前阶段
    search_results: Annotated[List[str], operator.add]
    draft: str
    review_score: int
    revision_count: int
    max_revisions: int


def analyze_input(state: WorkflowState) -> dict:
    """分析输入，决定是否需要搜索"""
    return {"stage": "search" if "?" in state["input"] else "generate"}


def route_from_analyze(state: WorkflowState) -> str:
    return state["stage"]                             # "search" 或 "generate"


def search_node(state: WorkflowState) -> dict:
    return {
        "search_results": [f"关于 {state['input']} 的结果"],
        "stage": "generate",
    }


def generate_node(state: WorkflowState) -> dict:
    context = "\n".join(state["search_results"])
    return {
        "draft": f"基于 '{state['input']}' 与上下文 '{context}' 生成的回答",
        "stage": "review",
    }


def review_node(state: WorkflowState) -> dict:
    score = min(10, len(state["draft"]) // 10)
    return {
        "review_score": score,
        "revision_count": state["revision_count"] + 1,
    }


def route_from_review(state: WorkflowState) -> str:
    if state["review_score"] >= 7:
        return "approved"
    if state["revision_count"] >= state["max_revisions"]:
        return "max_reached"
    return "needs_revision"


builder = StateGraph(WorkflowState)
builder.add_node("analyze", analyze_input)
builder.add_node("search", search_node)
builder.add_node("generate", generate_node)
builder.add_node("review", review_node)

builder.add_edge(START, "analyze")
builder.add_conditional_edges(
    "analyze", route_from_analyze, {"search": "search", "generate": "generate"}
)
builder.add_edge("search", "generate")
builder.add_edge("generate", "review")
builder.add_conditional_edges(
    "review",
    route_from_review,
    {
        "approved": END,
        "needs_revision": "generate",    # 循环回 generate
        "max_reached": END,
    },
)

app = builder.compile()
app.get_graph().print_ascii()
```

## 八、循环的终止条件

```python
from typing import TypedDict
from langgraph.graph import END


class SafeLoopState(TypedDict):
    counter: int
    max_iterations: int
    is_converged: bool


def safe_loop_router(state: SafeLoopState) -> str:
    """安全终止的循环路由：多重兜底"""
    if state["counter"] >= state["max_iterations"]:   # 条件 1：达到上限
        return END
    if state["is_converged"]:                         # 条件 2：已收敛
        return END
    return "loop_node"                                # 条件 3：继续
```

**永远记得设置循环终止条件！** 也可以在图级别限制：

```python
app.invoke(inputs, {"configurable": {"thread_id": "x"}, "recursion_limit": 50})
```

## 九、最佳实践

| 实践 | 说明 |
|------|------|
| **总是设置 max_iterations** | 防止无限循环导致 token 浪费与超时 |
| **路由函数保持简单** | 复杂判断放进节点，路由函数只做"读状态 → 返回目标" |
| **使用 Literal 类型** | 让 IDE 自动补全并检查路由目标是否合法 |
| **记录循环次数** | 在 State 中跟踪迭代次数，便于调试与兜底 |
| **错误退出** | 为异常情况设计退出路径（`error_handler`） |
| **动态分发用 `Send`** | 下游数量不确定时，别硬编码节点，用 `Send` |

## 十、本章小结

| 概念 | 一句话说明 |
|------|------------|
| **条件边** | 根据状态值决定下一步走向哪个节点 |
| **路由函数** | 返回目标节点名（或 `END`）的函数 |
| **循环** | 条件边指回自身/上游节点，必须有终止条件 |
| **`Command`** | 节点内直接决定跳转目标并更新状态 |
| **`Send`** | 运行时动态分发到多个下游（map-reduce） |
| **typed streaming v2** | 统一为 `StreamPart`（`type`/`ns`/`data`），便于解析 |
| **ReAct 循环** | `agent ⇄ tools` 的思考-行动循环 |
