# 4.2 状态管理与节点 —— 深入理解图的"血液"和"细胞"

> 📅 更新至 2026-10 · 技术栈基线见 [教程大纲](../教程大纲.md)

## 📖 导读

> **State（状态）是图的血液，Node（节点）是图的细胞。**

状态贯穿整个工作流，节点是状态的处理单元。本章不仅讲清楚 **`TypedDict` + reducer** 的状态设计，还要补齐两个生产必备能力：**`langgraph.store` 长期记忆**（跨会话记住用户）与**时间回溯**（回到任意历史检查点）。

## 二、状态（State）详解

### 2.1 State 的定义方式

```python
from typing import TypedDict, Annotated, List, Optional
import operator


# 方式一：TypedDict（推荐，类型安全、与 LangGraph 集成最好）
class AgentState(TypedDict):
    """Agent 的完整状态"""
    # 基础信息
    input: str                          # 用户输入
    output: str                         # 最终输出

    # 消息列表（自动追加，不是覆盖）
    messages: Annotated[List[dict], operator.add]

    # 任务状态
    current_step: int                   # 当前步数
    max_steps: int                      # 最大步数
    is_complete: bool                   # 是否完成

    # 工具调用
    tool_calls: Annotated[List[dict], operator.add]

    # 中间结果
    intermediate_results: Annotated[List[str], operator.add]

    # 错误信息
    error: Optional[str]                # 可选字段


# 方式二：Dataclass（适合需要默认值的场景）
from dataclasses import dataclass, field

@dataclass
class AgentStateDataclass:
    input: str = ""
    output: str = ""
    messages: List[dict] = field(default_factory=list)
    current_step: int = 0
    max_steps: int = 10
    is_complete: bool = False
```

> ⚠️ **常见坑**：节点里 `state["xxx"]` 读取的字段**必须在 `TypedDict` 中定义**，否则会抛 `KeyError`。新增字段时，记得同步更新 State 定义与初始输入。

### 2.2 状态更新机制

节点函数通过**返回字典**来更新状态，返回的 key 必须包含在 State 定义中。

```python
from typing import TypedDict, Annotated, List
import operator


class MyState(TypedDict):
    counter: int
    items: Annotated[List[str], operator.add]
    status: str


# 节点 1：更新基础字段（覆盖）
def node_increment(state: MyState) -> dict:
    """将 counter +1（覆盖旧值）"""
    return {"counter": state["counter"] + 1}


# 节点 2：追加到列表（使用 operator.add）
def node_add_item(state: MyState) -> dict:
    """追加一项到 items（自动追加，不是覆盖）"""
    return {"items": [f"item_{state['counter']}"]}
    # items 原本是 ["a"] → 现在是 ["a", "item_1"]


# 节点 3：不返回任何更新
def node_noop(state: MyState) -> None:
    """什么也不做：返回 None 或空 dict 均可"""
    return None


# 节点 4：返回多个字段
def node_multi_update(state: MyState) -> dict:
    """同时更新多个字段"""
    return {
        "counter": state["counter"] + 1,
        "status": "processing",
    }
```

### 2.3 reducer 机制详解

`Annotated[type, reducer]` 中的 `reducer` 决定了**如何合并多个节点的更新**。

```python
from typing import TypedDict, Annotated, List
import operator

class ReducerDemo(TypedDict):
    # 1. operator.add：追加模式（多个节点都返回该字段时合并）
    items: Annotated[List[str], operator.add]
    #    Node A: {"items": ["a"]} / Node B: {"items": ["b"]}
    #    → 最终 items = ["a", "b"] ✅ 合并了

    # 2. 默认（不注解）：覆盖模式（后面的覆盖前面的）
    name: str
    #    Node A: {"name": "Alice"} / Node B: {"name": "Bob"}
    #    → 最终 name = "Bob" ❌ Alice 被覆盖了

    # 3. 自定义 reducer
    counter: Annotated[int, lambda a, b: a + b]  # 自定义求和
```

### 2.4 消息专用 reducer：`add_messages`

处理对话消息时，用 `add_messages` 比 `operator.add` 更智能——它会**按消息 ID 去重/替换**，并正确维护 `HumanMessage` / `AIMessage` / `ToolMessage` 序列。

```python
from typing import Annotated
from langgraph.graph.message import add_messages
from langchain_core.messages import AnyMessage, HumanMessage, AIMessage


class MessageState(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]


def node(state: MessageState) -> dict:
    # 追加一条 AI 消息（也可传入 (id, message) 元组来替换同 ID 的消息）
    return {"messages": [AIMessage(content="你好！")]}
```

## 三、节点（Node）详解

### 3.1 节点的本质

节点就是一个**函数**（或可调用对象）：

- **输入**：当前状态（`TypedDict`），以及可选的内置参数（`store`、`config` 等）
- **输出**：部分状态更新（dict）或 None

```python
from typing import TypedDict


class MyState(TypedDict):
    output: str


# 3 种合法的 Node 形式

# 1. 普通函数（最常用）
def my_node(state: MyState) -> dict:
    return {"output": "结果"}

# 2. 异步函数（用 ainvoke/astream 运行时）
import asyncio

async def my_async_node(state: MyState) -> dict:
    await asyncio.sleep(0.1)
    return {"output": "结果"}

# 3. 可调用类
class MyNode:
    def __call__(self, state: MyState) -> dict:
        return {"output": "结果"}
```

### 3.2 节点的"依赖注入"：`store` 与 `config`

节点除 `state` 外，还可以通过关键字参数接收运行时注入的对象：

```python
from typing import TypedDict
from langgraph.store.base import BaseStore
from langchain_core.runnables import RunnableConfig


class MyState(TypedDict):
    output: str


def node_with_deps(state: MyState, *, store: BaseStore, config: RunnableConfig) -> dict:
    # store：长期记忆（需在 compile(store=...) 时提供）
    # config：运行时配置（thread_id、recursion_limit 等）
    thread_id = config["configurable"]["thread_id"]
    return {"output": f"线程 {thread_id} 处理完成"}
```

### 3.3 节点最佳实践

```python
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage
from typing import TypedDict, Annotated, List
import operator


class AgentState(TypedDict):
    messages: Annotated[List[dict], operator.add]
    next_action: str
    result: str


# 实践 1：一个节点只做一件事
def call_llm_node(state: AgentState) -> dict:
    """节点：调用 LLM（职责单一）"""
    llm = ChatOpenAI(model="gpt-5.5")
    response = llm.invoke(state["messages"])
    return {
        "messages": [response],
        "next_action": "analyze",   # 告诉路由下一步去哪
    }


# 实践 2：统一的错误处理（在节点内部消化异常）
def safe_node(state: AgentState) -> dict:
    """带错误处理的节点"""
    try:
        last = state["messages"][-1]
        content = last.content if hasattr(last, "content") else str(last)
        return {"result": content}
    except Exception as e:  # noqa: BLE001
        return {"result": f"处理失败: {e}"}
```

## 四、短时记忆：checkpointer（会话内记忆）

`checkpointer` 会把每一步状态落盘，用 `thread_id` 区分会话。这是**会话内**记忆。

```python
from typing import TypedDict, Annotated, List
import operator
from langchain_core.messages import HumanMessage
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import StateGraph, START, END


class AgentState(TypedDict):
    messages: Annotated[List[dict], operator.add]
    next_action: str
    result: str


builder = StateGraph(AgentState)
# ... 添加节点与边 ...
app = builder.compile(checkpointer=InMemorySaver())

config = {"configurable": {"thread_id": "session_1"}}

app.invoke({"messages": [HumanMessage(content="你好")]}, config)
# 第二次调用：相同 thread_id → 自动带上之前的状态
app.invoke({"messages": [HumanMessage(content="继续")]}, config)
```

| Checkpointer | 存储 | 场景 |
|--------------|------|------|
| `InMemorySaver` | 内存 | 开发调试 |
| `SqliteSaver` | SQLite 文件 | 单机持久化 |
| `PostgresSaver` | PostgreSQL | 生产、多实例 |

### 4.1 中断与恢复（interrupt / Command）

`interrupt()` 会在节点执行到该处时**暂停整张图**，把控制权交还给调用方；恢复时传入 `Command(resume=...)`，`interrupt()` 的返回值即为恢复值。

```python
from langgraph.types import interrupt, Command


class ConfirmState(TypedDict):
    question: str
    approved: bool


def confirm_node(state: ConfirmState) -> dict:
    # 在此暂停，等待外部决策
    decision = interrupt({"ask": state["question"]})
    return {"approved": bool(decision)}


builder = StateGraph(ConfirmState)
builder.add_node("confirm", confirm_node)
builder.add_edge(START, "confirm")
builder.add_edge("confirm", END)

app = builder.compile(checkpointer=InMemorySaver())
config = {"configurable": {"thread_id": "hitl-1"}}

# 第一次调用：会停在 interrupt 处
result = app.invoke({"question": "是否批准？", "approved": False}, config)
print(result["__interrupt__"])   # 查看中断载荷

# 恢复：把人工决策传回去
result = app.invoke(Command(resume=True), config)
print(result["approved"])        # True
```

> ⚠️ `interrupt()` 必须配合 `checkpointer` 使用，否则无法保存中断现场。`Command(resume=...)` 的值会作为 `interrupt()` 的返回值。

## 五、长时记忆：`langgraph.store` 实操（跨会话记忆）

checkpointer 只解决**同一 `thread_id` 内**的记忆。要**跨会话**记住用户（例如"用户偏好中文""用户是 VIP"），需要用 `langgraph.store`——一个独立的、按 `namespace` 组织的键值存储，支持语义检索。

| 维度 | checkpointer | store |
|------|--------------|-------|
| 作用范围 | 单个 `thread_id`（会话内） | 跨 `thread_id`（跨会话） |
| 数据形态 | 图的完整状态快照 | 任意 JSON 键值 + 可选向量 |
| 典型用途 | 多轮对话、断点恢复 | 用户画像、长期偏好、知识沉淀 |
| 访问方式 | `config["configurable"]["thread_id"]` | 节点参数 `store: BaseStore` |

### 5.1 完整可运行示例

```python
"""跨会话长期记忆：用 langgraph.store 记住用户"""
import os
import uuid

from typing import TypedDict, Annotated

from langchain_openai import ChatOpenAI
from langchain_core.messages import AnyMessage, HumanMessage, SystemMessage
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.store.memory import InMemoryStore
from langgraph.store.base import BaseStore


def get_llm() -> ChatOpenAI:
    """统一从环境变量读取模型配置"""
    return ChatOpenAI(
        model=os.getenv("LLM_MODEL_NAME", "gpt-5.5"),
        api_key=os.getenv("LLM_API_KEY"),
        base_url=os.getenv("LLM_BASE_URL"),
        temperature=0,
    )


class ChatState(TypedDict):
    user_id: str                                  # 记忆的命名空间依据
    messages: Annotated[list[AnyMessage], add_messages]
    memories: list[str]                           # 本次召回的记忆
    reply: str


def load_memory(state: ChatState, *, store: BaseStore) -> dict:
    """从长期记忆读取该用户的全部记忆"""
    namespace = ("memories", state["user_id"])
    items = store.search(namespace)               # 无 query：返回该命名空间下全部条目
    return {"memories": [item.value["fact"] for item in items]}


def chat_node(state: ChatState, *, store: BaseStore) -> dict:
    """基于记忆与对话历史生成回复"""
    mem_text = "\n".join(f"- {m}" for m in state["memories"]) or "（暂无）"
    system = SystemMessage(content=f"你是私人助手。已知用户信息：\n{mem_text}")
    reply = get_llm().invoke([system, *state["messages"]])
    return {"reply": reply.content}


def save_memory(state: ChatState, *, store: BaseStore) -> dict:
    """当用户要求"记住"时，写入长期记忆"""
    last_user = next(
        (m.content for m in reversed(state["messages"]) if isinstance(m, HumanMessage)),
        None,
    )
    if last_user and "记住" in last_user:
        namespace = ("memories", state["user_id"])
        # key 用 uuid，避免覆盖；也可用稳定 key（如 "preference"）实现"更新"
        store.put(namespace, key=str(uuid.uuid4()), value={"fact": last_user})
    return {}


# ===== 组装图 =====
builder = StateGraph(ChatState)
builder.add_node("load_memory", load_memory)
builder.add_node("chat", chat_node)
builder.add_node("save_memory", save_memory)

builder.add_edge(START, "load_memory")
builder.add_edge("load_memory", "chat")
builder.add_edge("chat", "save_memory")
builder.add_edge("save_memory", END)

# 同时挂载 checkpointer（会话内）与 store（跨会话）
store = InMemoryStore()
app = builder.compile(checkpointer=InMemorySaver(), store=store)


def chat(user_id: str, text: str, thread_id: str) -> str:
    config = {"configurable": {"thread_id": thread_id}}
    result = app.invoke(
        {"user_id": user_id, "messages": [HumanMessage(content=text)]},
        config,
    )
    return result["reply"]


if __name__ == "__main__":
    # 会话 A：告诉助手一个偏好
    print(chat("user-1", "请记住，我偏好用中文回答", "thread-a"))
    # 会话 B（新的 thread_id）：助手依然能召回该偏好
    print(chat("user-1", "我的语言偏好吗？", "thread-b"))
    # 用户 user-2 的记忆完全隔离
    print(chat("user-2", "我的语言偏好吗？", "thread-c"))
```

> ✅ 关键点：`thread_id` 决定**会话内**记忆，`store` 的 `namespace`（这里用 `("memories", user_id)`）决定**跨会话**记忆。换 `thread_id` 不会丢长期记忆，换 `user_id` 才会。

### 5.2 让长期记忆支持语义检索

默认 `InMemoryStore` 是精确键值。若希望按语义召回（"用户的饮食偏好" → 命中"我不吃辣"），给它配置一个嵌入索引：

```python
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

store = InMemoryStore(
    index={
        "embed": embeddings,   # 嵌入模型
        "dims": 1536,          # 维度
        "fields": ["fact"],    # 对 value 的哪些字段建索引
    }
)

# 之后即可语义检索
hits = store.search(("memories", "user-1"), query="用户的饮食偏好", limit=3)
```

> 🏭 **生产环境**：把 `InMemoryStore` 换成 `PostgresStore`（`from langgraph.store.postgres import PostgresStore`，需先 `uv add langgraph-checkpoint-postgres`），即可获得跨进程持久化的长期记忆。

## 六、时间回溯（Time Travel）

每次状态变更都会产生一个 **checkpoint**。借助 `get_state` / `get_state_history`，你可以查看任意历史状态，并**从历史某一步重放**（例如修改输入后重跑，探索不同分支）。

```python
from typing import TypedDict, Annotated
import operator
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import InMemorySaver


class CounterState(TypedDict):
    counter: int
    log: Annotated[list[str], operator.add]


def increment(state: CounterState) -> dict:
    n = state["counter"] + 1
    return {"counter": n, "log": [f"counter={n}"]}


builder = StateGraph(CounterState)
builder.add_node("increment", increment)
builder.add_edge(START, "increment")
builder.add_edge("increment", END)

app = builder.compile(checkpointer=InMemorySaver())
config = {"configurable": {"thread_id": "tt-1"}}

# 第一次传入初始输入，之后用 None 表示"在当前状态上继续"
app.invoke({"counter": 0, "log": []}, config)
app.invoke(None, config)
app.invoke(None, config)

# 1. 查看当前状态
snapshot = app.get_state(config)
print("当前:", snapshot.values)

# 2. 查看全部历史（最新的在前）
history = list(app.get_state_history(config))
for snap in history:
    ckpt = snap.config["configurable"]["checkpoint_id"]
    print(ckpt, snap.values.get("counter"), "next=", snap.next)

# 3. 回到历史某一步重放（snapshot.config 已包含 checkpoint_id）
old = history[-1]                        # 最早的一个检查点
app.invoke(None, old.config)             # 从该检查点继续
print("重放后:", app.get_state(old.config).values)
```

> ⚠️ **初始输入只给一次**：带 checkpointer 时，重复 `invoke` 会**在已有状态上继续**。第一次传初始输入，之后用 `invoke(None, config)` 继续，或传入真正的新输入。反复传 `{"counter": 0}` 会把它当作"更新"而覆盖计数。

## 七、复杂 State 设计模式

### 7.1 分层状态设计

```python
from typing import TypedDict, Annotated, List, Optional
import operator


class ResearchState(TypedDict):
    """研究任务的 State"""
    # 第一层：任务信息
    topic: str
    depth: str

    # 第二层：执行状态
    plan: List[str]
    current_step_index: int
    completed_steps: Annotated[List[str], operator.add]

    # 第三层：研究结果
    search_results: Annotated[List[dict], operator.add]
    report_draft: str
    report_final: str

    # 第四层：元信息
    total_tokens_used: int
    start_time: float
    error: Optional[str]
```

### 7.2 用 `Optional` 表达"条件字段"

```python
from typing import TypedDict, List, Optional


class ConditionalState(TypedDict):
    input: str
    task_type: str                      # "qa", "search", "write"
    answer: Optional[str]               # QA 场景
    query: Optional[str]                # 搜索场景
    search_results: Optional[List[str]]
    outline: Optional[List[str]]        # 写作场景
    draft: Optional[str]
```

> 💡 若某类任务字段差异极大，**优先拆成子图**（见 [4.4 子图](./04-子图.md)），而不是把所有字段堆进一个 State。

## 八、调试技巧

```python
# 1. 打印图结构
app.get_graph().print_ascii()

# 2. 逐节点调试：一个只打印不修改的节点
def debug_node(state: dict) -> dict:
    print("🔍 当前状态:")
    for key, value in state.items():
        if isinstance(value, list) and len(value) > 3:
            print(f"   {key}: [{len(value)} items] {value[:2]}...")
        else:
            print(f"   {key}: {value}")
    return {}          # 不修改状态

# 3. 流式执行，观察每个节点的更新
for chunk in app.stream({"counter": 0}, config, stream_mode="updates"):
    for node_name, update in chunk.items():
        print(f"节点 [{node_name}] 更新: {update}")

# 4. 检查历史检查点（定位"哪一步出了问题"）
for snap in app.get_state_history(config):
    print(snap.config["configurable"]["checkpoint_id"], snap.next)
```

## 九、常见问题

### ❌ 节点返回了 State 中未定义的字段

```python
from typing import TypedDict

class MyState(TypedDict):
    name: str

def bad_node(state: MyState) -> dict:
    return {"unknown_field": "xxx"}     # ❌ InvalidUpdateError

def good_node(state: MyState) -> dict:
    return {"name": "Alice"}            # ✅
```

### ❌ 读取了未定义的字段（KeyError）

```python
class MyState(TypedDict):
    name: str

def bad_node(state: MyState) -> dict:
    return {"name": state["nickname"]}  # ❌ KeyError：nickname 未定义

# ✅ 方案一：在 State 中补上字段
# ✅ 方案二：用 state.get("nickname", "")
```

### ❌ 使用 `operator.add` 却返回了非列表

```python
class MyState(TypedDict):
    items: Annotated[List[str], operator.add]

def bad_node(state: MyState) -> dict:
    return {"items": "single_item"}     # ❌ 类型错误

def good_node(state: MyState) -> dict:
    return {"items": ["single_item"]}   # ✅
```

### ❌ 长期记忆没生效

- 检查 `compile(store=store)` 是否传入了 `store`；
- 检查节点是否声明了 `*, store: BaseStore` 参数；
- 检查读写用的是**同一个 namespace**（如 `("memories", user_id)`）。

## 十、本章小结

| 概念 | 要点 |
|------|------|
| **State** | 共享数据结构，定义为 `TypedDict`，字段必须先声明 |
| **reducer** | `Annotated[T, reducer]` 决定多节点更新的合并方式 |
| **add_messages** | 消息专用 reducer，自动去重/替换同 ID 消息 |
| **checkpointer** | 会话内记忆 + 断点恢复，按 `thread_id` 隔离 |
| **store** | 跨会话长期记忆，按 `namespace` 组织，支持语义检索 |
| **interrupt / Command** | 暂停与恢复，实现人机协同 |
| **时间回溯** | `get_state_history` 查看历史，`invoke(None, snap.config)` 重放 |
| **调试** | `print_ascii()` + `stream(stream_mode="updates")` |
