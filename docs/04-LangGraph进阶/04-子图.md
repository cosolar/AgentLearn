# 4.4 子图与模块化 —— 构建可复用的工作流组件

> 📅 更新至 2026-10 · 技术栈基线见 [教程大纲](../教程大纲.md)

## 📖 导读

> **当一张图变得太大时，就该拆分了。子图就是 LangGraph 的"函数"——可复用、可组合、可独立测试。**

随着 Agent 系统复杂度增加，一张图可能包含几十个节点。把相关节点封装成**子图（Subgraph）**，可以显著提升可维护性和复用性。就像你不会把整个程序写在一个函数里，你也不该把整个工作流放在一张图里。

> 📌 本章最重要的一条纪律：**子图与主图的 State 字段必须对齐**——要么子图 schema 是主图的"子集"（共享字段），要么用一个"映射节点"显式转换。否则会出现字段读不到（`KeyError`）或更新丢失。

## 二、为什么需要子图？

```text
❌ 一张大图：
input → analyze → search → parse → filter → rank →
generate → review → revise → review → output

✅ 拆分子图：
input → [Research Subgraph] → [Writing Subgraph] → output
            ├── search               ├── generate
            ├── parse                ├── review
            ├── filter               └── revise
            └── rank
```

| 好处 | 说明 |
|------|------|
| **可复用** | 子图可在不同项目、不同主图中复用 |
| **可测试** | 子图可独立 `compile().invoke()` 测试 |
| **可维护** | 每个子图职责清晰，降低认知负担 |
| **可组合** | 子图像积木一样拼装，甚至可嵌套 |

---

## 三、把子图接入主图的三种方式

### 3.1 方式一：子图 schema 是主图 schema 的子集（最常用）

只要子图声明的字段都能在主图 state 中找到，就可以**直接把编译后的子图作为节点**。LangGraph 会把主图 state 中同名字段喂给子图，并把子图的输出合并回主图。

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END


# ===== 主图状态 =====
class MainState(TypedDict):
    topic: str
    search_results: list[str]
    research_summary: str
    final_content: str


# ===== 子图状态：字段是 MainState 的子集（同名） =====
class ResearchState(TypedDict):
    topic: str
    search_results: list[str]
    research_summary: str


def create_research_subgraph() -> StateGraph:
    """研究子图：搜索 → 分析"""

    def search_node(state: ResearchState) -> dict:
        print(f"  [子图] 搜索: {state['topic']}")
        return {"search_results": [f"{state['topic']} 资料1", f"{state['topic']} 资料2"]}

    def analyze_node(state: ResearchState) -> dict:
        print(f"  [子图] 分析 {len(state['search_results'])} 条资料")
        return {"research_summary": f"{state['topic']}：共 {len(state['search_results'])} 条资料"}

    sg = StateGraph(ResearchState)
    sg.add_node("search", search_node)
    sg.add_node("analyze", analyze_node)
    sg.add_edge(START, "search")
    sg.add_edge("search", "analyze")
    sg.add_edge("analyze", END)
    return sg


def finalize_node(state: MainState) -> dict:
    return {"final_content": f"{state['topic']} 报告：{state['research_summary']}"}


# ===== 主图：直接挂载编译后的子图 =====
builder = StateGraph(MainState)
builder.add_node("research", create_research_subgraph().compile())   # 子图作为一个节点
builder.add_node("finalize", finalize_node)

builder.add_edge(START, "research")
builder.add_edge("research", "finalize")
builder.add_edge("finalize", END)

app = builder.compile()
app.get_graph().print_ascii()

result = app.invoke({
    "topic": "AI Agent",
    "search_results": [],
    "research_summary": "",
    "final_content": "",
})
print(result["final_content"])
```

> ✅ 关键：`ResearchState` 的字段（`topic` / `search_results` / `research_summary`）在主图中**同名存在**，所以无需任何映射。这也是**最推荐**的子图设计方式。

### 3.2 方式二：直接传入未编译的 builder

LangGraph 也支持把**未编译的 `StateGraph`** 直接作为节点传入，编译交给主图统一完成：

```python
builder.add_node("research", create_research_subgraph())   # 不调用 .compile()
```

适合"子图不需要被独立调用/测试"的场景。若希望子图能独立运行，仍建议显式 `.compile()`。

### 3.3 方式三：schema 不同 → 用"映射节点"转换

当子图关心的是**完全不同的字段**（例如子图只处理 `query` / `hits`），无法直接挂载，需要写一个**包装节点**做双向映射。

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END


class MainState(TypedDict):
    topic: str
    search_results: list[str]


class SearchState(TypedDict):     # 与 MainState 字段完全不同
    query: str
    hits: list[str]


def create_search_subgraph():
    def do_search(state: SearchState) -> dict:
        return {"hits": [f"{state['query']} 命中1", f"{state['query']} 命中2"]}

    sg = StateGraph(SearchState)
    sg.add_node("do_search", do_search)
    sg.add_edge(START, "do_search")
    sg.add_edge("do_search", END)
    return sg.compile()


search_app = create_search_subgraph()


def search_wrapper(state: MainState) -> dict:
    """映射节点：MainState → SearchState → MainState"""
    sub_input = {"query": state["topic"], "hits": []}     # 主 → 子
    sub_output = search_app.invoke(sub_input)             # 运行子图
    return {"search_results": sub_output["hits"]}         # 子 → 主


builder = StateGraph(MainState)
builder.add_node("search", search_wrapper)
builder.add_edge(START, "search")
builder.add_edge("search", END)

app = builder.compile()
print(app.invoke({"topic": "RAG", "search_results": []})["search_results"])
```

| 方式 | 适用 | 代价 |
|------|------|------|
| 子集 schema（3.1） | 字段天然对齐 | 无 |
| 未编译 builder（3.2） | 不需要独立调用子图 | 无法单独测试 |
| 映射节点（3.3） | 子图字段独立/差异大 | 需手写映射代码 |

## 四、嵌套子图（子图里再套子图）

子图内部同样可以挂载更小的子图，形成层次结构。

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END


class State(TypedDict):
    text: str
    cleaned: str
    tokens: list[str]
    summary: str


# 最内层：分词子图
def create_tokenize_subgraph():
    def tokenize(state: State) -> dict:
        return {"tokens": state["cleaned"].split()}

    sg = StateGraph(State)
    sg.add_node("tokenize", tokenize)
    sg.add_edge(START, "tokenize")
    sg.add_edge("tokenize", END)
    return sg.compile()


# 中间层：清洗子图（内部再挂分词子图）
def create_clean_subgraph():
    def clean(state: State) -> dict:
        return {"cleaned": " ".join(state["text"].split())}

    sg = StateGraph(State)
    sg.add_node("clean", clean)
    sg.add_node("tokenize", create_tokenize_subgraph())     # ← 嵌套
    sg.add_edge(START, "clean")
    sg.add_edge("clean", "tokenize")
    sg.add_edge("tokenize", END)
    return sg.compile()


# 最外层：主图
def summarize(state: State) -> dict:
    return {"summary": f"共 {len(state['tokens'])} 个词"}


builder = StateGraph(State)
builder.add_node("pipeline", create_clean_subgraph())       # ← 挂载中间层子图
builder.add_node("summarize", summarize)
builder.add_edge(START, "pipeline")
builder.add_edge("pipeline", "summarize")
builder.add_edge("summarize", END)

app = builder.compile()
result = app.invoke({"text": "  Hello   LangGraph   World  ", "cleaned": "", "tokens": [], "summary": ""})
print(result["summary"])    # 共 3 个词
```

## 五、复用：同一子图挂载到多处

编译一次，多处复用——这是子图价值的核心体现。

```python
from typing import TypedDict, Annotated
import operator
from langgraph.graph import StateGraph, START, END


class ReuseState(TypedDict):
    draft: str
    reviewed: Annotated[list[str], operator.add]   # 收集每次审查结果


def create_review_subgraph():
    """通用审查子图：对 draft 做一次检查"""
    def check(state: ReuseState) -> dict:
        return {"reviewed": [f"检查 draft（{len(state['draft'])} 字）"]}

    sg = StateGraph(ReuseState)
    sg.add_node("check", check)
    sg.add_edge(START, "check")
    sg.add_edge("check", END)
    return sg.compile()


review = create_review_subgraph()          # 只编译一次

builder = StateGraph(ReuseState)
builder.add_node("spell_check", review)    # 复用 1：拼写检查
builder.add_node("logic_check", review)    # 复用 2：逻辑检查

builder.add_edge(START, "spell_check")
builder.add_edge("spell_check", "logic_check")
builder.add_edge("logic_check", END)

app = builder.compile()
result = app.invoke({"draft": "这是一个测试草稿", "reviewed": []})
print(result["reviewed"])   # ['检查 draft（7 字）', '检查 draft（7 字）']
```

> ⚠️ 复用同一子图时，多个实例**并发写同一字段**要用 reducer（这里 `operator.add`），否则后写覆盖先写。

## 六、实战：内容创作工作流（3 个子图）

```text
主图：ContentWorkflow
│
├── [Research Subgraph]  ← 研究子图（search → analyze）
├── [Writing Subgraph]   ← 写作子图（outline → write）
└── [Review Subgraph]    ← 审查子图（quality → polish）
```

```python
"""内容创作工作流：三个子图串联"""
from typing import TypedDict, Annotated, List
import operator
from langgraph.graph import StateGraph, START, END


# ===== 主图状态（所有子图字段均为其子集） =====
class ContentState(TypedDict):
    topic: str
    search_results: Annotated[List[str], operator.add]
    research_summary: str
    outline: List[str]
    draft: str
    quality_score: int
    final_content: str


# ===== 子图 1：研究 =====
def create_research_subgraph():
    def search(state: ContentState) -> dict:
        return {"search_results": [f"{state['topic']} 概念", f"{state['topic']} 实践"]}

    def analyze(state: ContentState) -> dict:
        return {"research_summary": f"{state['topic']} 研究摘要（{len(state['search_results'])} 条）"}

    sg = StateGraph(ContentState)
    sg.add_node("search", search)
    sg.add_node("analyze", analyze)
    sg.add_edge(START, "search")
    sg.add_edge("search", "analyze")
    sg.add_edge("analyze", END)
    return sg.compile()


# ===== 子图 2：写作 =====
def create_writing_subgraph():
    def outline(state: ContentState) -> dict:
        return {"outline": [f"{state['topic']} 概述", f"{state['topic']} 实践"]}

    def write(state: ContentState) -> dict:
        body = "\n".join(f"## {s}\n正文..." for s in state["outline"])
        return {"draft": f"# {state['topic']}\n{body}"}

    sg = StateGraph(ContentState)
    sg.add_node("outline", outline)
    sg.add_node("write", write)
    sg.add_edge(START, "outline")
    sg.add_edge("outline", "write")
    sg.add_edge("write", END)
    return sg.compile()


# ===== 子图 3：审查 =====
def create_review_subgraph():
    def quality(state: ContentState) -> dict:
        return {"quality_score": min(10, len(state["draft"]) // 20)}

    def polish(state: ContentState) -> dict:
        return {"final_content": state["draft"] + "\n\n*（已润色）*"}

    sg = StateGraph(ContentState)
    sg.add_node("quality", quality)
    sg.add_node("polish", polish)
    sg.add_edge(START, "quality")
    sg.add_edge("quality", "polish")
    sg.add_edge("polish", END)
    return sg.compile()


# ===== 主图组装 =====
def create_content_workflow():
    builder = StateGraph(ContentState)
    builder.add_node("research", create_research_subgraph())
    builder.add_node("writing", create_writing_subgraph())
    builder.add_node("review", create_review_subgraph())

    builder.add_edge(START, "research")
    builder.add_edge("research", "writing")
    builder.add_edge("writing", "review")
    builder.add_edge("review", END)
    return builder.compile()


if __name__ == "__main__":
    app = create_content_workflow()
    app.get_graph().print_ascii()          # 可看到主图 + 子图的层次结构

    result = app.invoke({
        "topic": "AI Agent",
        "search_results": [],
        "research_summary": "",
        "outline": [],
        "draft": "",
        "quality_score": 0,
        "final_content": "",
    })
    print(f"质量评分: {result['quality_score']}/10")
    print(result["final_content"][:80], "...")
```

## 七、调试子图

```python
# 1. 单独测试子图（无需主图）
research = create_research_subgraph()
out = research.invoke({
    "topic": "测试", "search_results": [], "research_summary": "",
    "outline": [], "draft": "", "quality_score": 0, "final_content": "",
})
print("子图独立测试通过:", out["research_summary"])

# 2. 查看完整层次结构
app = create_content_workflow()
app.get_graph().print_ascii()

# 3. 流式执行，观察子图内部的 ns（命名空间）
for part in app.stream(
    {"topic": "测试", "search_results": [], "research_summary": "",
     "outline": [], "draft": "", "quality_score": 0, "final_content": ""},
    stream_mode="updates",
    version="v2",
):
    # part["ns"] 形如 ("research:abc123",) 表示来自子图内部
    print(part["ns"], "→", list(part["data"].keys()))
```

> 💡 类型化流式的 `ns` 字段能区分事件来自主图还是哪个子图，是调试多子图系统的利器。

## 八、子图的设计原则

| 原则 | 说明 |
|------|------|
| **字段对齐优先** | 子图 schema 尽量做成主图子集，避免手写映射 |
| **单一职责** | 一个子图只做一类事（研究/写作/审查各一个） |
| **输入输出明确** | 若必须独立 schema，用映射节点写清"进什么、出什么" |
| **并发写用 reducer** | 多个子图/节点写同一字段时用 `Annotated[..., operator.add]` |
| **可独立测试** | 子图应能 `compile().invoke()` 单独跑通 |

---

## 九、本章小结

| 概念 | 一句话说明 |
|------|------------|
| **子图** | 封装多个节点的完整图，可作为主图的一个节点 |
| **子集 schema** | 子图字段是主图字段的子集，可直接挂载（推荐） |
| **映射节点** | schema 不同时，用包装节点做双向字段转换 |
| **嵌套子图** | 子图内部可再挂载子图，形成层次结构 |
| **复用** | 编译一次，可挂载到多个节点 |
| **并发写** | 多实例写同一字段必须用 reducer |
| **`ns`** | 流式输出中的命名空间，用于区分主图/子图事件 |
