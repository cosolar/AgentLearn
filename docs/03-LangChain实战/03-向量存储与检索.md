# 3.3 向量存储与检索 —— 为 Agent 装上"语义搜索引擎"

> 📅 更新至 2026-10 · 技术栈基线见 [知识库大纲](../知识库大纲.md)

## 📖 导读

> **传统搜索靠关键词匹配，向量搜索靠语义理解。**

向量存储（Vector Store）是 RAG（检索增强生成）的核心基础设施。它让 Agent 能在海量文本中找到**语义上最相关**的内容——即使关键词不完全匹配。

本章目标是**"够用"的检索能力**：讲清 Embedding 原理、`langchain_chroma` 的持久化用法、相似度检索与一个**最小可运行的 RAG 闭环**。更深度的检索优化（混合检索、重排、GraphRAG、Agentic RAG）留到[第 5 部分 RAG 系统](../05-RAG系统/01-RAG原理.md)。

**本节基线**：Python ≥ 3.12 · `langchain>=1.4.5` · `langchain-chroma` · `chromadb>=1.5.9` · `langchain-openai>=1.7.1`。

## 二、Embedding：把文本变成向量

### 2.1 直观理解

```text
传统搜索：
用户搜"猫" → 只匹配包含"猫"字的文档 → 错过"猫咪""小猫""feline"

向量搜索：
用户搜"猫" → 转换为向量 [0.1, 0.5, -0.3, ...]
           → 找到向量空间中最接近的内容
           → "猫咪" [0.12, 0.48, -0.28, ...] ✅ 匹配
           → "宠物" [0.15, 0.45, -0.20, ...] ✅ 相关
           → "汽车" [-0.1, 0.1, 0.6, ...]    ❌ 无关
```

### 2.2 文本 → 向量

```python
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

vector_1 = embeddings.embed_query("猫是一种可爱的动物")
vector_2 = embeddings.embed_query("猫咪很讨人喜欢")
vector_3 = embeddings.embed_query("汽车需要定期保养")

print(f"向量维度: {len(vector_1)}")       # 1536
print(f"向量（前 5 个）: {vector_1[:5]}")
```

**余弦相似度**（值越接近 1 越相似）：

```python
import numpy as np


def cosine_similarity(v1: list[float], v2: list[float]) -> float:
    return float(np.dot(v1, v2) / (np.linalg.norm(v1) * np.linalg.norm(v2)))


print(f"猫 vs 猫咪: {cosine_similarity(vector_1, vector_2):.3f}")  # ~0.85
print(f"猫 vs 汽车: {cosine_similarity(vector_1, vector_3):.3f}")  # ~0.30
```

> 💡 批量场景用 `embeddings.embed_documents([...])` 一次算多条，比逐条 `embed_query` 更快。

### 2.3 Embedding 模型对比

| 模型 | 维度 | 特点 | 适用场景 |
|------|------|------|----------|
| `text-embedding-3-small` | 1536 | 性价比高、速度快 | **默认推荐（通用/英文）** |
| `text-embedding-3-large` | 3072 | 精度更高、更贵 | 精度要求极高 |
| `voyage-3` / `voyage-3-large` | 1024 / 2048 | 检索质量领先 | 高质量 RAG |
| `bge-m3` | 1024 | 开源、多语言、稠密+稀疏 | 私有化、中文 |
| `Qwen3-Embedding` | 可变 | 开源、中文强 | 国产化部署 |

> 💡 **2026 实践**：中文/多语言优先 `bge-m3`、`Qwen3-Embedding`；商用质量优先 `voyage-3`；纯英文入门用 `text-embedding-3-small` 即可（成本约为 large 的 1/5）。

也可以用统一入口初始化：

```python
from langchain.embeddings import init_embeddings

embeddings = init_embeddings("openai:text-embedding-3-small")
```

## 三、Chroma 实战

### 3.1 安装

```bash
uv add langchain-chroma chromadb
```

> ⚠️ **Chroma 已从 `langchain-community` 拆分**为独立包 `langchain-chroma`。请使用 `from langchain_chroma import Chroma`，**不要**再用 `langchain_community.vectorstores.Chroma`。

### 3.2 完整流程

```python
from langchain_chroma import Chroma
from langchain_core.documents import Document
from langchain_openai import OpenAIEmbeddings

# 1) 准备文档
documents = [
    Document(
        page_content="AI Agent 是一种能够自主感知环境、理解意图、做出决策并采取行动的智能软件系统。",
        metadata={"source": "agent_intro", "page": 1},
    ),
    Document(
        page_content="LangChain 是一个用于构建 LLM 应用的开发框架，提供模型调用、链式组合、Agent 等能力。",
        metadata={"source": "langchain_intro", "page": 2},
    ),
    Document(
        page_content="向量数据库将文本转换为向量进行存储，支持基于语义相似度的检索。",
        metadata={"source": "vector_db", "page": 3},
    ),
]

# 2) 初始化 Embedding 模型
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

# 3) 创建向量存储（自动计算向量并索引；指定 persist_directory 即持久化）
vectorstore = Chroma.from_documents(
    documents=documents,
    embedding=embeddings,
    persist_directory="./chroma_db",
)

# 4) 检索
results = vectorstore.similarity_search("什么是 AI Agent？", k=2)
for i, doc in enumerate(results, 1):
    print(f"结果 {i}: {doc.page_content[:40]}... | 来源: {doc.metadata['source']}")
```

### 3.3 持久化（重要）

```python
# ✅ langchain-chroma 在写入时会自动落盘到 persist_directory，无需手动持久化
vectorstore = Chroma.from_documents(
    documents=documents,
    embedding=embeddings,
    persist_directory="./chroma_db",   # 指定即自动持久化
)

# ✅ 下次启动直接从磁盘加载已有集合
vectorstore = Chroma(
    embedding_function=embeddings,
    persist_directory="./chroma_db",
)

# ✅ 增量写入（同样自动落盘）
vectorstore.add_documents([
    Document(page_content="RAG 是检索增强生成。", metadata={"source": "rag_intro"})
])
```

```python
# ❌ 已弃用：不要调用 vectorstore.persist()

```

### 3.4 基本检索方式

```python
# 1) 基础相似度搜索
results = vectorstore.similarity_search("AI Agent 是什么？", k=3)

# 2) 带分数的相似度搜索（分数越高越相关）
scored = vectorstore.similarity_search_with_relevance_scores("AI Agent 是什么？", k=3)
for doc, score in scored:
    print(f"分数: {score:.3f} | {doc.page_content[:30]}...")

# 3) 用向量直接检索
query_vector = embeddings.embed_query("AI Agent 是什么？")
results = vectorstore.similarity_search_by_vector(query_vector, k=3)

# 4) MMR（最大边际相关性，兼顾相关性与多样性）
results = vectorstore.max_marginal_relevance_search(
    "AI Agent 是什么？",
    k=3,
    fetch_k=10,        # 先取 10 个候选，再从中挑 3 个多样化的
    lambda_mult=0.5,   # 0=纯多样，1=纯相关
)
```

## 四、检索策略与调优

### 4.1 相似度搜索 vs MMR

| 策略 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **相似度搜索** | 选和查询最像的 K 个 | 相关度高 | 结果可能重复 |
| **MMR** | 选相关 + 多样化的 K 个 | 结果覆盖广 | 可能遗漏最相关项 |

```text
相似度搜索（query = "Python 编程"）：
1. Python 基础语法   2. Python 函数式编程   3. Python 面向对象

MMR：
1. Python 基础语法   2. Java 和 Python 对比   3. 编程入门指南   ← 覆盖不同角度
```

### 4.2 参数调优

| 参数 | 说明 | 推荐值 | 效果 |
|------|------|--------|------|
| **k** | 返回结果数 | 3–5 | k 越大信息越多，但噪声也越多 |
| **score_threshold** | 分数阈值 | 0.5–0.7 | 过滤低质量结果 |
| **fetch_k** | MMR 候选数 | k × 2–3 | 增加多样性 |
| **lambda_mult** | MMR 多样性权重 | 0.5 | 0=纯多样，1=纯相关 |

### 4.3 元数据过滤

```python
# 简单过滤：只查报告类文档
results = vectorstore.similarity_search(
    "AI 趋势",
    k=3,
    filter={"category": "report"},
)

# 复合过滤（Chroma 支持 $and / $or）
results = vectorstore.similarity_search(
    "Python 新特性",
    k=3,
    filter={
        "$and": [
            {"category": {"$eq": "release"}},
            {"date": {"$gte": "2023-01-01"}},
        ]
    },
)
```

## 五、构建检索器与最小 RAG 闭环

### 5.1 从向量库创建检索器

```python
retriever = vectorstore.as_retriever(
    search_type="similarity",          # 或 "mmr"
    search_kwargs={"k": 3},
)

docs = retriever.invoke("什么是 AI Agent？")
```

### 5.2 最小 RAG 闭环（LCEL）

用 LCEL 把"检索 → 拼上下文 → 生成"串成一条链，这就是最基础的 RAG：

```python
"""最小 RAG 闭环：检索 → 增强 → 生成"""
import os

from dotenv import load_dotenv
from langchain_chroma import Chroma
from langchain_core.documents import Document
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough
from langchain_openai import ChatOpenAI, OpenAIEmbeddings

load_dotenv()

# 1) 建库（示例；真实项目从磁盘加载）
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma.from_documents(
    documents=[
        Document(page_content="AI Agent 的核心能力包括感知、推理、行动和记忆。",
                 metadata={"source": "agent_intro.md"}),
        Document(page_content="RAG 是检索增强生成的缩写，用于提升 LLM 回答的准确性与时效性。",
                 metadata={"source": "rag_intro.md"}),
    ],
    embedding=embeddings,
    persist_directory="./chroma_db",
)
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

# 2) 模型（统一从 LLM_* 读取）
llm = ChatOpenAI(
    model=os.getenv("LLM_MODEL_NAME", "gpt-5.5"),
    api_key=os.getenv("LLM_API_KEY"),
    base_url=os.getenv("LLM_BASE_URL"),
    temperature=0,
)


def format_docs(docs) -> str:
    """把检索结果拼成带来源标注的上下文。"""
    return "\n\n".join(
        f"[来源: {d.metadata.get('source', '未知')}]\n{d.page_content}" for d in docs
    )


# 3) 组装 RAG 链
prompt = ChatPromptTemplate.from_template(
    "基于以下参考信息回答问题；若参考信息不足，请直接说“未找到相关信息”。\n\n"
    "参考信息：\n{context}\n\n问题：{question}"
)

rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | llm
    | StrOutputParser()
)

answer = rag_chain.invoke("AI Agent 有哪些核心能力？")
print(answer)
```

> 💡 这就是"够用"的 RAG。当检索质量不理想时，再考虑[混合检索、重排、查询改写](../05-RAG系统/04-优化策略.md)。

## 六、把检索变成 Agent 工具（通往 Agentic RAG）

上面是"检索一次 → 生成一次"的固定流程。在 Agent 场景下，更常见的是把检索封装成一个**工具**，让 Agent 自主决定"要不要检索、检索几次、换什么关键词"：

```python
from langchain.agents import create_agent
from langchain.tools import tool


@tool
def search_knowledge_base(query: str) -> str:
    """在企业知识库中检索。可多次调用，用不同角度的关键词。"""
    docs = vectorstore.similarity_search(query, k=4)
    if not docs:
        return "没有检索到相关内容。"
    return "\n\n".join(f"[{d.metadata.get('source', '未知')}]\n{d.page_content}" for d in docs)


agent = create_agent(
    model="openai:gpt-5.5",
    tools=[search_knowledge_base],
    system_prompt="你是知识库助手。回答前必须先检索；找不到依据就直说不知道，不要编造。",
)

result = agent.invoke({"messages": [{"role": "user", "content": "我们的报销流程是什么？"}]})
print(result["messages"][-1].content)
```

> 📌 这就是 **Agentic RAG** 的雏形。完整形态（查询改写、重排、答案校验都变成工具）见 [5.1 RAG 原理 · Agentic RAG](../05-RAG系统/01-RAG原理.md)。

## 七、最佳实践

### 7.1 文档预处理

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter


def split_documents(documents, chunk_size: int = 500, chunk_overlap: int = 50):
    """把长文档切成适合检索的块，并补充元数据。"""
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=chunk_size,
        chunk_overlap=chunk_overlap,
        separators=["\n\n", "\n", "。", ".", " "],
    )
    chunks = splitter.split_documents(documents)
    for chunk in chunks:
        chunk.metadata["length"] = len(chunk.page_content)
    return chunks
```

### 7.2 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| **检索结果不相关** | 查询太短/模糊 | 查询扩展、HyDE |
| **结果重复度高** | 分块重叠或语义相似 | 使用 MMR 检索 |
| **检索速度慢** | 数据量太大 | 用 FAISS 或索引优化 |
| **重启后数据丢失** | 未指定 `persist_directory` | 指定持久化目录（自动落盘） |

## 本章小结

| 概念 | 一句话说明 |
|------|------------|
| **向量嵌入** | 把文本转为数值向量，语义相近的文本向量距离近 |
| **Chroma** | 轻量级向量库，`langchain-chroma` 独立包，适合开发测试 |
| **持久化** | 指定 `persist_directory` 即自动落盘；**禁止** `persist()` |
| **相似度搜索** | 找到和查询最像的 K 个结果 |
| **MMR** | 找相关 + 多样化的结果 |
| **检索器** | `as_retriever()` 封装向量库的统一检索接口 |
| **元数据过滤** | 按来源、日期等维度筛选检索范围 |
| **最小 RAG 闭环** | 检索 → 拼上下文 → 生成（LCEL 一条链） |
| **Agentic RAG** | 把检索封装成工具，让 Agent 自主检索 |
