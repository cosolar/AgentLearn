# 3.2 模型调用与工具集成 —— 让 LLM 之手触及真实世界

> 📅 更新至 2026-10 · 技术栈基线见 [知识库大纲](../知识库大纲.md)

## 📖 导读

> **模型是 Agent 的大脑，工具是 Agent 的双手。没有工具，Agent 只能思考不能行动。**

LangChain 统一了 100+ 个 LLM 的调用接口，并提供了一整套工具系统。本章讲清四件事：

1. **`init_chat_model`** —— 一行代码在 OpenAI / Anthropic / DeepSeek 之间切换；
2. **`@tool`** —— 把任意 Python 函数变成 Agent 可调用的工具，以及**工具错误处理**；
3. **`ToolRuntime`** —— 让工具安全地读取运行时上下文（用户身份、会话状态、长期记忆）；
4. **结构化输出** —— 用 `response_format` 让模型返回可验证的 Pydantic 对象。

**本节基线**：Python ≥ 3.12 · `langchain>=1.4.5` · `langchain-openai>=1.7.1` · `langchain-anthropic>=1.7.6`。模型统一 `gpt-5.5`，从 `LLM_MODEL_NAME` / `LLM_API_KEY` / `LLM_BASE_URL` 读取。

## 二、统一模型接口：`init_chat_model`

### 2.1 基础用法

`init_chat_model` 是所有模型的统一入口，返回标准的 `BaseChatModel`：

```python
import os

from langchain.chat_models import init_chat_model

# 方式一：provider 前缀（推荐）
llm = init_chat_model("openai:gpt-5.5", temperature=0)

# 方式二：model + model_provider
llm = init_chat_model("gpt-5.5", model_provider="openai", temperature=0)

# 方式三：读取本教程统一的 LLM_* 环境变量（跨厂商切换）
llm = init_chat_model(
    os.getenv("LLM_MODEL_NAME", "gpt-5.5"),
    model_provider="openai",
    api_key=os.getenv("LLM_API_KEY"),
    base_url=os.getenv("LLM_BASE_URL"),
    temperature=0,
)
```

### 2.2 多厂商切换

```python
# === OpenAI ===
from langchain_openai import ChatOpenAI
openai_llm = ChatOpenAI(model="gpt-5.5")

# === Anthropic (Claude) ===
from langchain_anthropic import ChatAnthropic
claude_llm = ChatAnthropic(model="claude-sonnet-4-6")

# === 兼容 OpenAI API 的任意服务（vLLM / LM Studio / 通义 / DeepSeek 等）===
from langchain_openai import ChatOpenAI
local_llm = ChatOpenAI(
    base_url="http://localhost:8000/v1",
    api_key="not-needed",
    model="local-model",
)
```

| 提供商 | `model_provider` | 需要的集成包 | 示例模型名 |
|--------|------------------|--------------|------------|
| OpenAI | `openai` | `langchain-openai` | `gpt-5.5` |
| Anthropic | `anthropic` | `langchain-anthropic` | `claude-sonnet-4-6` |
| DeepSeek | `deepseek` | `langchain-deepseek` | `deepseek-chat` |
| Ollama（本地） | `ollama` | `langchain-ollama` | `qwen3:8b` |

> 💡 **切换成本**：把模型名从 `openai:gpt-5.5` 改成 `anthropic:claude-sonnet-4-6`，其余代码（工具、Agent、结构化输出）**一行都不用改**。

### 2.3 三种调用模式

```python
from langchain.messages import HumanMessage, SystemMessage

messages = [
    SystemMessage(content="你是一个专业的 AI 导师，用通俗的语言解释概念。"),
    HumanMessage(content="什么是 AI Agent？"),
]

# 1) 一次性调用
response = llm.invoke(messages)
print(response.content)

# 2) 流式调用（逐 token，适合实时显示）
for chunk in llm.stream("请用 200 字介绍 AI Agent。"):
    print(chunk.content, end="", flush=True)

# 3) 批量调用（同一次请求处理多条，OpenAI 支持）
responses = llm.batch([
    [HumanMessage(content="解释 Python 的 list")],
    [HumanMessage(content="解释 Python 的 dict")],
])
```

```python
# 4) 异步调用（高并发场景）
import asyncio

from langchain.messages import HumanMessage


async def async_demo():
    questions = ["Python 是什么？", "什么是 AI？", "RAG 是什么？"]
    responses = await asyncio.gather(*(llm.ainvoke(q) for q in questions))
    for q, r in zip(questions, responses):
        print(f"Q: {q}\nA: {r.content[:50]}...\n")


asyncio.run(async_demo())
```

> 📌 四种模式都有对应的 `ainvoke` / `astream` / `abatch` 异步版本。

## 三、工具系统详解

### 3.1 工具的四个要素

| 要素 | 说明 | 示例 |
|------|------|------|
| **名称** | 唯一标识（默认取函数名） | `search_web` |
| **描述** | 告诉 LLM **何时**使用（取自 docstring） | "搜索互联网，获取实时信息" |
| **参数** | 输入参数定义（取自类型注解 / `args_schema`） | `query: str` |
| **实现** | 实际执行的代码 | `return requests.get(...)` |

### 3.2 用 `@tool` 定义工具

```python
from langchain.tools import tool


@tool
def search_knowledge_base(query: str, k: int = 3) -> str:
    """搜索内部知识库，返回与查询最相关的资料片段。

    Args:
        query: 检索关键词。
        k: 返回的片段数量，默认 3。
    """
    docs = vectorstore.similarity_search(query, k=k)
    return "\n\n".join(d.page_content for d in docs)


@tool
def calculate(expression: str) -> str:
    """执行数学计算，输入一个数学表达式。"""
    try:
        return str(eval(expression, {"__builtins__": {}}, {}))
    except Exception as e:
        return f"计算错误: {e}"
```

**用 `args_schema` 做参数校验（推荐用于多参数工具）**：

```python
from pydantic import BaseModel, Field
from langchain.tools import tool


class WeatherInput(BaseModel):
    """查询天气的输入参数。"""

    city: str = Field(description="城市名称，如 北京、上海")
    date: str = Field(default="today", description="日期，格式 YYYY-MM-DD，默认为今天")


@tool(args_schema=WeatherInput)
def get_weather(city: str, date: str = "today") -> str:
    """查询指定城市在指定日期的天气。"""
    return f"{city} {date} 天气：晴，25°C"
```

### 3.3 用 `BaseTool` 类定义（需要状态或复杂逻辑时）

```python
from langchain.tools import BaseTool
from pydantic import BaseModel, Field


class WeatherInput(BaseModel):
    city: str = Field(description="城市名称")


class WeatherTool(BaseTool):
    """天气查询工具。"""

    name: str = "get_weather"
    description: str = "查询指定城市的天气"
    args_schema: type[BaseModel] = WeatherInput

    def _run(self, city: str) -> str:
        return f"{city} 天气：晴，25°C"
```

> 💡 大多数场景用 `@tool` 即可；只有当工具需要持有状态、连接池或复杂初始化时，才继承 `BaseTool`。

### 3.4 工具设计原则

| 原则 | 错误做法 | 正确做法 |
|------|----------|----------|
| **描述清晰** | "一个搜索工具" | "搜索互联网获取中文技术文档，输入关键词，返回前 3 条结果" |
| **参数明确** | `data: dict` | `query: str, max_results: int = 5` |
| **单一职责** | 一个大工具做所有事 | 拆分为多个小工具各司其职 |
| **错误处理** | 裸抛异常 | 返回友好错误信息（见第五节） |
| **返回字符串** | 返回不可序列化对象 | 返回 `str`（或可序列化内容），便于回传模型 |

**工具数量原则**：

```text
0-2 个工具：Agent 很快会用，但能力有限
3-8 个工具：✅ 最佳区间，Agent 能准确选择
8-15 个工具：开始出现选择困难，偶尔选错
15+ 个工具：❌ Agent 频繁误选，需要简化或加 LLMToolSelectorMiddleware
```

## 四、工具错误处理

工具报错时，**不要让异常直接打断 Agent 循环**。三种处理方式，按粒度从细到粗：

### 4.1 方式一：工具内部兜底（最简单）

```python
@tool
def calculate(expression: str) -> str:
    """执行数学计算。"""
    try:
        return str(eval(expression, {"__builtins__": {}}, {}))
    except Exception as e:
        return f"计算失败：{e}，请检查表达式。"  # 把错误变成可读结果
```

### 4.2 方式二：`ToolException` + `handle_tool_error`

工具抛 `ToolException` 时，框架会按 `handle_tool_error` 的配置把它转成一条 `ToolMessage` 回传给模型，而不是让程序崩溃：

```python
from langchain.tools import tool
from langchain_core.tools import ToolException


@tool
def query_database(sql: str) -> str:
    """执行只读 SQL 查询。"""
    if not sql.strip().lower().startswith("select"):
        raise ToolException("仅允许 SELECT 查询，请修改后重试。")
    return "查询结果：……"


# handle_tool_error 可为 True / 字符串 / 可调用对象
query_database.handle_tool_error = True
```

### 4.3 方式三：`@wrap_tool_call` 统一拦截（推荐）

用一个中间件统一处理**所有**工具的错误，无需每个工具各写一遍：

```python
from langchain.agents import create_agent
from langchain.agents.middleware import wrap_tool_call
from langchain.messages import ToolMessage
from langchain.tools.tool_node import ToolCallRequest


@wrap_tool_call
def handle_tool_errors(request: ToolCallRequest, handler):
    """把所有工具异常转成友好的 ToolMessage，交给模型自行处理。"""
    try:
        return handler(request)                 # 正常执行工具
    except Exception as e:
        return ToolMessage(
            content=f"工具执行出错：{type(e).__name__} - {e}。请检查输入或换个方式。",
            tool_call_id=request.tool_call["id"],
        )


agent = create_agent(
    model="openai:gpt-5.5",
    tools=[search_web, calculate, query_database],
    middleware=[handle_tool_errors],
)
```

> 📌 `@wrap_tool_call` 来自 `langchain.agents.middleware`；`request` 的类型 `ToolCallRequest` 来自 `langchain.tools.tool_node`。

**错误分类建议**：

| 错误层 | 处理策略 |
|--------|----------|
| 参数校验失败 | 把可修正字段反馈给模型，限制重试次数 |
| 429 / 临时网络失败 | 有界退避（`ToolRetryMiddleware`） |
| 权限拒绝 | 不重试，返回明确的授权错误 |
| 外部写入超时 | 先查幂等结果，再决定是否重试 |
| 模型循环无进展 | `ModelCallLimitMiddleware` / `ToolCallLimitMiddleware` |

## 五、工具与运行时上下文：`ToolRuntime`

给工具加一个 `runtime: ToolRuntime` 参数，它会被**自动注入**（对模型不可见，不进 tool schema），从而读取运行时信息：

| 字段 | 含义 |
|------|------|
| `runtime.state` | 短期记忆：`messages` + 自定义字段（可读写） |
| `runtime.context` | `invoke(context=...)` 传入的上下文（配合 `context_schema`） |
| `runtime.store` | 跨会话长期记忆（LangGraph store） |
| `runtime.tool_call_id` | 当前工具调用 ID |

```python
from dataclasses import dataclass

from langchain.agents import create_agent
from langchain.tools import tool, ToolRuntime


@dataclass
class UserContext:
    user_id: str
    user_role: str          # "admin" 或 "guest"


@tool
def count_messages(runtime: ToolRuntime) -> str:
    """统计当前对话的消息数量。"""
    return f"当前对话有 {len(runtime.state['messages'])} 条消息。"


@tool
def load_profile(runtime: ToolRuntime) -> str:
    """读取当前用户画像（不把身份硬编码进 Prompt）。"""
    return f"用户 {runtime.context.user_id}（角色：{runtime.context.user_role}）"


agent = create_agent(
    model="openai:gpt-5.5",
    tools=[count_messages, load_profile],
    context_schema=UserContext,
)

result = agent.invoke(
    {"messages": [{"role": "user", "content": "我是谁？对话里几条消息了？"}]},
    context=UserContext(user_id="u_42", user_role="admin"),
)
print(result["messages"][-1].content)
```

> 💡 用 `context_schema` + `runtime.context` 传递 `user_id`、数据库连接、租户配置等运行时依赖，比塞进 Prompt 或全局变量更安全、更可测试。

## 六、绑定工具到模型

### 6.1 `bind_tools` 与工具调用（理解原理）

```python
from langchain.chat_models import init_chat_model
from langchain.messages import HumanMessage, SystemMessage, ToolMessage
from langchain.tools import tool


@tool
def search_web(query: str) -> str:
    """搜索网络获取实时信息。"""
    return f"关于「{query}」的搜索结果……"


tools_by_name = {"search_web": search_web}

llm = init_chat_model("openai:gpt-5.5", temperature=0)
llm_with_tools = llm.bind_tools([search_web])

messages = [
    SystemMessage(content="你是一个智能助手，需要实时信息时使用工具。"),
    HumanMessage(content="搜索一下 AI Agent 的最新发展"),
]

# 1) 模型决定是否调用工具
ai = llm_with_tools.invoke(messages)
messages.append(ai)

# 2) 若模型发起工具调用，逐个执行并回传结果
for call in ai.tool_calls:
    result = tools_by_name[call["name"]].invoke(call["args"])
    messages.append(ToolMessage(content=str(result), tool_call_id=call["id"]))

# 3) 把工具结果交回模型，生成最终回答
final = llm_with_tools.invoke(messages)
print(final.content)
```

### 6.2 生产推荐：交给 `create_agent`

上面的手动循环是理解原理的好方式，但生产中应直接使用 `create_agent`——它会自动完成"模型 → 工具 → 回传模型 → 直至结束"的完整循环：

```python
from langchain.agents import create_agent

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[search_web, calculate],
    system_prompt="你是一个智能助手，需要实时信息或计算时主动使用工具。",
)

result = agent.invoke({"messages": [{"role": "user", "content": "搜索 AI Agent 趋势并算一下 128*256"}]})
print(result["messages"][-1].content)
```

## 七、结构化输出（`response_format`）

需要模型返回**可验证的结构化数据**时，用 `create_agent` 的 `response_format`——结构化输出在**主循环内**生成，无需额外一次 LLM 调用。

### 7.1 三种策略

```python
from pydantic import BaseModel, Field
from langchain.agents import create_agent
from langchain.agents.structured_output import ToolStrategy, ProviderStrategy


class WeatherReport(BaseModel):
    """天气报告。"""

    city: str = Field(description="城市名称")
    temperature: float = Field(description="温度（摄氏度）")
    condition: str = Field(description="天气状况")


# ① ProviderStrategy：利用厂商原生结构化输出（OpenAI / Claude 等），最快
agent = create_agent(model="openai:gpt-5.5", tools=[], response_format=ProviderStrategy(WeatherReport))

# ② ToolStrategy：把 Schema 伪装成一个"工具"，兼容所有支持工具调用的模型
agent = create_agent(model="openai:gpt-5.5", tools=[], response_format=ToolStrategy(WeatherReport))

# ③ AutoStrategy：直接传 Pydantic 模型，让框架自动选择最优策略
agent = create_agent(model="openai:gpt-5.5", tools=[], response_format=WeatherReport)

result = agent.invoke({"messages": [{"role": "user", "content": "杭州今天晴天，25 度"}]})
report = result["structured_response"]      # 已验证的 Pydantic 实例
print(report.city, report.temperature, report.condition)
```

| 策略 | 原理 | 兼容性 | 速度 |
|------|------|--------|------|
| `ProviderStrategy` | 用厂商原生 `response_format` | 部分模型（GPT-4o+ / Claude 3+） | 快（无额外工具调用） |
| `ToolStrategy` | 伪装成工具调用 | 所有支持 function calling 的模型 | 略慢 |
| `AutoStrategy` | 直接传 Pydantic 模型，自动选择 | 自动适配 | 自动最优 |

> ⚠️ 部分模型（如某些国产模型）不支持 `ProviderStrategy`，会直接报错；此时改用 `ToolStrategy` 或直接传 Pydantic 模型（AutoStrategy）。

### 7.2 错误重试

`ToolStrategy` 支持在输出不符合 Schema 时把错误反馈给模型重试：

```python
from langchain.agents.structured_output import ToolStrategy

# True：自动重试；也可传字符串模板或自定义处理函数
strategy = ToolStrategy(schema=WeatherReport, handle_errors="格式有误，请按 {error} 修正后重新输出")
agent = create_agent(model="openai:gpt-5.5", tools=[], response_format=strategy)
```

## 九、最佳实践

| 实践 | 说明 |
|------|------|
| **描述清晰** | docstring 直接决定 LLM 能否正确选择工具，务必写清"何时使用" |
| **参数用类型注解** | `str` / `int` / `list[str]` 帮助模型正确传参 |
| **优雅的错误处理** | 工具异常返回友好信息，或用 `@wrap_tool_call` 统一拦截 |
| **控制工具数量** | 最适合 3–8 个；过多时加 `LLMToolSelectorMiddleware` |
| **优先 `@tool`** | 比 `BaseTool` 类更简洁；需要状态时再用类 |
| **上下文用 `ToolRuntime`** | 不要把 `user_id`、密钥硬编码进 Prompt 或全局变量 |
| **结构化输出用 `response_format`** | 比 `PydanticOutputParser` 更可靠、更省一次调用 |

## 本章小结

| 概念 | 要点 |
|------|------|
| **`init_chat_model`** | 统一模型入口，provider 前缀一行切换任意厂商 |
| **调用模式** | `invoke` / `stream` / `batch` + 异步版 |
| **`@tool`** | 把函数变成工具；docstring 是给模型的说明书 |
| **工具错误处理** | 内部兜底 → `ToolException` → `@wrap_tool_call` 三层 |
| **`ToolRuntime`** | 工具安全读取 `state` / `context` / `store` |
| **`bind_tools`** | 工具调用底层机制；生产用 `create_agent` |
| **`response_format`** | `ToolStrategy` / `ProviderStrategy` / AutoStrategy 结构化输出 |
| **MCP** | 直接接入现成工具，无需自建 |
