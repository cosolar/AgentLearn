## 一、安装与环境（1–6）

| # | 症状 / 报错信息 | 根本原因 | 解决方案 | 相关章节 |
|:-:|:----------------|:---------|:---------|:---------|
| 1 | `uv: command not found` | uv 未安装或未加入 PATH | 用官方脚本安装（`curl -LsSf https://astral.sh/uv/install.sh \| sh`）后**重开终端**；Windows 用 `irm https://astral.sh/uv/install.ps1 \| iex` | [1.2](../01-入门基础/02-开发环境搭建.md) |
| 2 | `requires-python >=3.12` 报错 / 语法不支持 `X \| Y` | 系统默认 Python < 3.12 | `uv python install 3.12`，项目内用 `uv run` 自动锁定 3.12；或 `uv venv --python 3.12` | [1.2](../01-入门基础/02-开发环境搭建.md) |
| 3 | `ModuleNotFoundError: No module named 'langchain'` | 直接用了系统 Python，未激活 uv 虚拟环境 | 一律用 `uv run python xxx.py`；或 `source .venv/bin/activate`（Windows: `.venv\Scripts\activate`） | [1.2](../01-入门基础/02-开发环境搭建.md) |
| 4 | 依赖冲突 / `ResolutionImpossible` | 手工 `pip install` 混用、版本不满足基线 | 用 `uv add` 管理，不要用 pip；冲突时 `uv lock --upgrade` 后 `uv sync` | [1.2](../01-入门基础/02-开发环境搭建.md) |
| 5 | `ImportError: cannot import name 'X' from 'langchain'` | `langchain` 与 `langchain-core` 版本不匹配 | 对齐基线：`langchain>=1.4.5`、`langchain-core>=1.6.10`；`uv sync` 重装 | [3.1](../03-LangChain实战/01-LangChain核心组件.md) |
| 6 | Windows 控制台中文乱码 / `UnicodeEncodeError` | 默认编码非 UTF-8 | 设 `PYTHONUTF8=1`，或 `chcp 65001`；写文件显式 `encoding="utf-8"` | [1.2](../01-入门基础/02-开发环境搭建.md) |

## 二、模型调用（7–14）

| # | 症状 / 报错信息 | 根本原因 | 解决方案 | 相关章节 |
|:-:|:----------------|:---------|:---------|:---------|
| 7 | `AuthenticationError` / HTTP 401 | `LLM_API_KEY` 缺失、过期或未加载 `.env` | 确认 `load_dotenv()` 在读取前调用；打印 `os.getenv("LLM_API_KEY")[:6]` 验证；检查 `.env` 未被 `.gitignore` 忽略且确实存在 | [1.2](../01-入门基础/02-开发环境搭建.md) |
| 8 | HTTP 403 / `PermissionDeniedError` | Key 无权访问该模型，或区域/组织未开通 | 换用有权限的模型名；检查服务商控制台的组织/项目配额；第三方网关需确认模型白名单 | [3.2](../03-LangChain实战/02-模型调用与工具.md) |
| 9 | HTTP 429 `RateLimitError` | 触发速率/并发限制 | 加**有界退避重试**（指数退避 + 抖动）；降低并发；生产用 `ToolRetryMiddleware` / 请求排队 | [3.2](../03-LangChain实战/02-模型调用与工具.md) |
| 10 | `APITimeoutError` / 请求长时间无响应 | 网络抖动、base_url 不可达、单次请求过大 | 设超时与重试参数；检查 `LLM_BASE_URL` 是否可 `curl` 通；缩短输入、流式输出降低首字延迟 | [7.1](../07-生产部署/01-API服务部署.md) |
| 11 | `NotFoundError: model not found` / 404 | 模型名拼写错误，或 base_url 指向的服务不含该模型 | 核对模型名（教程统一 `gpt-5.5`）；自建/代理服务确认其暴露的模型 ID | [3.2](../03-LangChain实战/02-模型调用与工具.md) |
| 12 | 返回内容为空字符串 | 命中内容过滤、`max_tokens` 过小、或 reasoning 模型的思考未回填 | 提高 `max_tokens`；检查是否被安全策略拦截；对推理型模型读取 `content_blocks` 而非仅 `content` | [3.1](../03-LangChain实战/01-LangChain核心组件.md) |
| 13 | `Connection error` / 连不上本地模型 | 本地服务（Ollama/vLLM）未启动或端口错 | 确认服务在监听（如 `http://localhost:8000/v1`）；`base_url` 必须带 `/v1`；`api_key` 可填占位符 | [3.2](../03-LangChain实战/02-模型调用与工具.md) |
| 14 | 切换厂商后全部报错 | 未安装对应集成包（如 `langchain-anthropic`） | `uv add langchain-anthropic`；并确认 `model_provider` 与包一致 | [3.2](../03-LangChain实战/02-模型调用与工具.md) |

## 四、LangGraph 与状态（20–26）

| # | 症状 / 报错信息 | 根本原因 | 解决方案 | 相关章节 |
|:-:|:----------------|:---------|:---------|:---------|
| 20 | `ValueError: Checkpointer requires one or more of the following 'configurable' keys: thread_id` | `invoke` 时未传 `thread_id` | 传入 `config = {"configurable": {"thread_id": "s1"}}` | [3.4](../03-LangChain实战/04-构建聊天Agent.md) |
| 21 | 多轮对话"失忆" | 每次调用换了 `thread_id`，或压根没配 checkpointer | 同一会话固定同一 `thread_id`；`create_agent(..., checkpointer=InMemorySaver())` | [2.4](../02-核心概念/04-记忆机制.md) |
| 22 | `KeyError: 'xxx'` | 节点读写的字段未在 State（`TypedDict`）中声明 | 在 State 中补上该字段，并在初始输入中给初值 | [4.2](../04-LangGraph进阶/02-状态管理与节点.md) |
| 23 | `InvalidUpdateError` / 并行节点写同一字段冲突 | 多节点写同字段但未定义 reducer | 用 `Annotated[T, operator.add]`（或 `add_messages`）声明合并方式 | [4.2](../04-LangGraph进阶/02-状态管理与节点.md) |
| 24 | 消息列表被"覆盖"而非追加 | 用了默认覆盖语义 | 消息字段用 `Annotated[list[AnyMessage], add_messages]` | [4.2](../04-LangGraph进阶/02-状态管理与节点.md) |
| 25 | 图不终止 / 无限循环 | 条件边始终返回同一分支，或循环无退出条件 | 加计数器 + 条件退出；用 `ModelCallLimitMiddleware` 兜底；检查 `route` 函数返回值 | [4.3](../04-LangGraph进阶/03-路由与循环.md) |
| 26 | `interrupt` 恢复后行为异常 / 重复执行 | 恢复时换了 `thread_id`，或用 `invoke` 传了新输入而非 `Command(resume=...)` | 恢复必须**同一 `thread_id`** + `app.invoke(Command(resume=...), config)` | [4.5](../04-LangGraph进阶/05-实战工作流Agent.md) |

## 九、包结构与版本（41–43）

> 2026-10 基线（`langchain` 1.4.5 / `langgraph` 1.2.15）把若干模块拆成了**独立发行包**，本节专治"路径没变但包没装"的迷惑性报错。

| # | 症状 / 报错信息 | 根本原因 | 解决方案 | 相关章节 |
|:-:|:----------------|:---------|:---------|:---------|
| 41 | `ImportError: cannot import name 'StateGraph' from 'langgraph'` | `langgraph` 顶层已不再导出符号（1.2+ 无顶层 `__init__` 的导出） | 一律走子模块路径：`from langgraph.graph import StateGraph, START, END`；`MessagesState` / `add_messages` 同在此模块 | [4.1](../04-LangGraph进阶/01-LangGraph基础.md) |
| 42 | `ModuleNotFoundError: No module named 'langgraph.prebuilt'` | `langgraph.prebuilt` 自 1.2 起由独立包 `langgraph-prebuilt` 提供；用 `--no-deps` 安装或手工裁剪依赖时缺失 | `uv add langgraph-prebuilt`（正常 `uv add langgraph` 会自动带上） | [4.3](../04-LangGraph进阶/03-路由与循环.md) |
| 43 | `ModuleNotFoundError: No module named 'langgraph.checkpoint.postgres'` | 持久化后端是独立包，`langgraph-checkpoint` 只含内存态与序列化 | `uv add langgraph-checkpoint-postgres`（同时提供 `langgraph.store.postgres`）；SQLite 用 `langgraph-checkpoint-sqlite` | [2.4](../02-核心概念/04-记忆机制.md) |

## 通用调试流程

定位"是 harness 问题还是模型问题"，按下面**五步**走：

```text
① 看最底层报错栈
   栈底那一行才是真正的失败点。是 ImportError / AuthError / ValidationError？
   → 90% 是环境、配置、接口问题，先别怀疑模型。

② 隔离变量：把 Agent 降级为"裸模型"
   直接 llm.invoke("hello") 能通吗？
   ├─ 不能 → 问题在【模型层】：Key / base_url / 模型名 / 网络
   └─ 能   → 问题在【Harness 层】：继续第 ③ 步

③ 打开 trace 观察循环
   agent.stream(..., stream_mode="updates") 逐步打印：
   模型有没有产出 tool_calls？工具有没有被调用？参数对不对？结果回传了吗？
   → 看清"断在哪一步"

④ 二分法：固定一半、替换一半
   固定 prompt，换模型 → 排除模型
   固定模型，换 prompt → 排除提示词
   固定工具，换 mock 返回 → 排除外部依赖

⑤ 最小复现
   把失败的场景压到最小（1 个工具、1 条消息、最短 prompt）。
   能复现 → 精确定位；不能复现 → 大概率是上下文/状态污染（检查 thread_id 与历史）。
```

| 判断问题归属 | 典型信号 | 优先动作 |
|:-------------|:---------|:---------|
| **模型问题** | 裸模型调用就报错 / 换模型即好 / 输出质量差 | 检查 Key、base_url、模型名、限额；换模型对比 |
| **Harness 问题** | 模型能跑但 Agent 不干活 / 工具不调 / 循环不终止 / 状态错乱 | 看 trace 逐步定位；检查工具描述、reducer、checkpointer、路由函数 |
| **数据/检索问题** | 答非所问但模型正常 | 单独测 retriever 的召回质量；看 chunk 与相似度分数 |

> 🎯 **一条经验**：**先用 `stream_mode="updates"` 把"模型每一步看到了什么"打印出来**——绝大多数"玄学问题"在 trace 面前会立刻现形。
