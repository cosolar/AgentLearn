## 一、Agent 基础

**Agent（智能体）**：一种**涌现行为**——一个有目标、会使用工具、能根据观察结果自我纠正的系统；不是某个类，而是"模型 + Harness"共同产生的行为。→ 深入：[1.1 AI Agent 导论](../01-入门基础/01-AI-Agent导论.md)

**Harness（驾驭层 / 智能体外壳）**：模型之外的一切——提示词、工具、上下文、权限、验证、生命周期管理；`Agent = Model + Harness`，模型是商品，Harness 是护城河。→ 深入：[9.1 什么是 Agent Harness](../09-驾驭工程/01-什么是AgentHarness.md)

**Chatbot（聊天机器人）**：只做"输入 → 输出"的单轮/多轮对话系统，**不会自主调用工具、不会自我纠错**；与 Agent 的关键分野是"能否行动与自省"。→ 深入：[1.1 AI Agent 导论](../01-入门基础/01-AI-Agent导论.md)

**LLM（大语言模型）**：基于 Transformer 的自回归语言模型，是 Agent 的"大脑"；知识止于训练数据，需靠 RAG/工具补齐时效与私有知识。→ 深入：[1.1 AI Agent 导论](../01-入门基础/01-AI-Agent导论.md)

**Token（词元）**：模型处理文本的最小计量单位；一切成本、延迟、上下文窗口都以 token 计。→ 深入：[6.3 成本控制](../06-高级主题/03-成本控制.md)

**TAO / ReAct（Thought-Action-Observation）**：Agent 的基本心跳——**思考 → 行动 → 观察**循环，直到模型不再调用工具为止。→ 深入：[2.3 Agent 核心架构](../02-核心概念/03-Agent核心架构.md)

**Tool（工具）**：Agent 的"双手"，一个带**名称 / 描述 / 参数 / 实现**四要素的函数；docstring 决定模型能否正确选择它。→ 深入：[3.2 模型调用与工具](../03-LangChain实战/02-模型调用与工具.md)

**Function Calling（函数调用）**：模型输出**结构化工具调用请求**（而非自然语言）的原生能力，是 Tool 生效的底层机制。→ 深入：[3.2 模型调用与工具](../03-LangChain实战/02-模型调用与工具.md)

**Middleware（中间件）**：LangChain v1 的**控制面**，在 Agent 循环的固定切点插入钩子（压缩历史、人工审批、PII 脱敏、调用限额、工具错误拦截）。→ 深入：[3.1 LangChain v1 核心组件](../03-LangChain实战/01-LangChain核心组件.md)

**System Prompt（系统提示词）**：位于消息序列头部、定义 Agent 角色与约束的常驻指令；应保持**稳定前缀**以利 prompt cache。→ 深入：[2.1 Prompt 与上下文工程](../02-核心概念/01-Prompt与上下文工程.md)

**Chain / LCEL（链 / LangChain 表达式语言）**：用 `|` 声明式连接多个 Runnable 的线性编排，适合确定性流程。→ 深入：[2.2 Chain 模式详解](../02-核心概念/02-Chain模式详解.md)

**Runnable（可运行协议）**：LangChain 的统一接口，提供 `invoke` / `stream` / `batch` 及其异步版本；Chain、模型、检索器都实现它。→ 深入：[2.2 Chain 模式详解](../02-核心概念/02-Chain模式详解.md)

**Structured Output（结构化输出）**：让模型返回**可验证的 Pydantic 对象**（`response_format`），在主循环内生成，无需额外一次调用。→ 深入：[3.2 模型调用与工具](../03-LangChain实战/02-模型调用与工具.md)

**Context Engineering（上下文工程）**：目标函数是"找到**最小的一组高信号 token**，最大化达成期望结果的概率"；比换更强模型更影响成功率。→ 深入：[9.3 上下文工程与压缩](../09-驾驭工程/03-上下文工程与压缩.md)

## 二、编排与状态（LangGraph）

**StateGraph（状态图）**：LangGraph 的核心抽象——以"共享状态 + 节点 + 边"描述可含分支、循环、并行的有向图。→ 深入：[4.1 LangGraph 基础](../04-LangGraph进阶/01-LangGraph基础.md)

**Node（节点）**：图中处理状态的函数单元，接收状态、返回"部分更新"的 dict。→ 深入：[4.2 状态管理与节点](../04-LangGraph进阶/02-状态管理与节点.md)

**Edge / Conditional Edge（边 / 条件边）**：边控制执行顺序；条件边根据状态**动态决定**下一步走向，是实现路由与循环的关键。→ 深入：[4.3 路由与循环](../04-LangGraph进阶/03-路由与循环.md)

**State（状态）**：图中所有节点共享的数据容器（通常用 `TypedDict` 定义），是图的"血液"。→ 深入：[4.2 状态管理与节点](../04-LangGraph进阶/02-状态管理与节点.md)

**Reducer（归约函数）**：`Annotated[T, reducer]` 中决定**多个节点的更新如何合并**的函数；`operator.add` 追加、默认覆盖、`add_messages` 智能合并消息。→ 深入：[4.2 状态管理与节点](../04-LangGraph进阶/02-状态管理与节点.md)

**Checkpointer（检查点存储器）**：按 `thread_id` 持久化每一步图状态的组件，是多轮记忆与断点恢复的基础；新路径为 `from langgraph.checkpoint.memory import InMemorySaver`。→ 深入：[4.2 状态管理与节点](../04-LangGraph进阶/02-状态管理与节点.md)

**Thread（线程 / 会话）**：由 `thread_id` 标识的一条独立对话状态序列；同 `thread_id` 共享记忆，不同 `thread_id` 完全隔离。→ 深入：[3.4 构建聊天 Agent](../03-LangChain实战/04-构建聊天Agent.md)

**Subgraph（子图）**：嵌入主图的完整子工作流，用于模块化与复用，需处理状态 schema 映射。→ 深入：[4.4 子图](../04-LangGraph进阶/04-子图.md)

**Interrupt（中断）**：在指定节点暂停执行并保存状态的机制（`interrupt()`），配合 `Command(resume=...)` 恢复，是人机协同的底层原语。→ 深入：[4.5 实战工作流 Agent](../04-LangGraph进阶/05-实战工作流Agent.md)

**HITL（Human-in-the-Loop，人在回路）**：在 Agent 关键节点引入人工审批/修改的协作模式，用 `interrupt` + checkpointer 实现"暂停—审阅—恢复"。→ 深入：[4.5 实战工作流 Agent](../04-LangGraph进阶/05-实战工作流Agent.md)

**Durable Execution（持久化执行）**：把每一步状态落盘，使长时任务可在崩溃/中断后**从检查点恢复**，而非从头重跑。→ 深入：[4.5 实战工作流 Agent](../04-LangGraph进阶/05-实战工作流Agent.md)

**Supervisor（主管）**：一个主管 Agent 动态决定"下一个该谁执行"的多 Agent 拓扑，最实用、最易控。→ 深入：[6.1 多 Agent 协作](../06-高级主题/01-多Agent协作.md)

**Handoff（移交）**：Agent 之间**无中心地传递控制权**（客服升级、专家转接），在 LangGraph 中用 `Command(goto=...)` 实现。→ 深入：[6.1 多 Agent 协作](../06-高级主题/01-多Agent协作.md)

**Fan-out / Send（扇出 / 动态分发）**：运行时根据状态决定**生成多少个下游任务**并并行执行（如按文档列表批量处理），由 `Send` 原语实现。→ 深入：[4.3 路由与循环](../04-LangGraph进阶/03-路由与循环.md)

**Command**：LangGraph 中可同时**更新状态并指定跳转目标**（`Command(update=..., goto=...)`）的原语，常用于路由与 handoff。→ 深入：[4.3 路由与循环](../04-LangGraph进阶/03-路由与循环.md)

**Store（长期记忆存储）**：跨会话、跨线程的持久化记忆（`runtime.store`），与 checkpointer 的"会话级短期记忆"互补。→ 深入：[4.2 状态管理与节点](../04-LangGraph进阶/02-状态管理与节点.md)

## 三、Harness 工程

**Context Rot（上下文腐化）**：上下文变长导致性能**主动退化**的现象——即使关键信息都在窗口内，注意力被稀释后表现仍下降，与"窗口够不够大"无关。→ 深入：[9.3 上下文工程与压缩](../09-驾驭工程/03-上下文工程与压缩.md)

**Compaction（压缩）**：接近上下文上限时，把较早历史**总结为结构化摘要**并替换原文的策略（保留架构决策与未解 bug，丢弃冗余工具输出）。→ 深入：[9.3 上下文工程与压缩](../09-驾驭工程/03-上下文工程与压缩.md)

**Summarization（摘要 / 总结）**：压缩的核心手段；LangChain 以 `SummarizationMiddleware` 形式提供，可保留最近一段原文不压缩。→ 深入：[9.3 上下文工程与压缩](../09-驾驭工程/03-上下文工程与压缩.md)

**Prompt Cache（提示缓存）**：服务端对**稳定前缀**的 KV 做缓存以降低延迟与成本；因是前缀匹配，压缩必须**从后往前**以保护前缀。→ 深入：[9.3 上下文工程与压缩](../09-驾驭工程/03-上下文工程与压缩.md)

**Progressive Disclosure（渐进式披露）**：**先披露元信息/入口，需要时再层层展开细节**——Skill 的加载机制（metadata 常驻 → 正文按需 → 资源更深层）。→ 深入：[9.10 标准与 Skills](../09-驾驭工程/10-标准与Skills.md)

**deny-first（拒绝优先）**：权限判定顺序——**先查 deny，deny 永远覆盖 allow**；且被 deny 的工具对模型**不可见**，是"不依赖模型判断力"的硬保证。→ 深入：[9.4 权限护栏与沙箱](../09-驾驭工程/04-权限护栏与沙箱.md)

**Guardrail（护栏）**：输入 / 输出 / 工具三级的**可执行检查**，把"约束"从提示词落到确定性代码。→ 深入：[9.4 权限护栏与沙箱](../09-驾驭工程/04-权限护栏与沙箱.md)

**Tripwire（熔断线）**：护栏触发时的"熔断"信号，触发即**立即停机**（而非"继续但忽略"）。→ 深入：[9.2 十二大模块解剖](../09-驾驭工程/02-十二大模块解剖.md)

**Back-pressure（背压）**：让失败的**后果立刻反馈回模型**，迫使它自我修正——测试/构建/类型检查构成自愈回路。→ 深入：[9.5 验证循环](../09-驾驭工程/05-验证循环.md)

**Stop Gate（停止门）**：Agent 准备结束时执行的**确定性验证门**（如跑测试、跑 lint），不通过则打回并把失败当 observation 注入。→ 深入：[9.5 验证循环](../09-驾驭工程/05-验证循环.md)

**Andon Cord（安灯绳）**：源自精益制造，指 `Lint → Review → UnitTest → E2E` 的验证链，**任一环节拉绳即停**。→ 深入：[9.5 验证循环](../09-驾驭工程/05-验证循环.md)

**MVH（Minimum Viable Harness，最小可行 Harness）**：约 700 行、纯标准库可运行的最小骨架（编排循环 + 三重预算 + deny-first + 两段式压缩 + 验证门 + 埋点），是生产 Harness 的起点。→ 深入：[9.8 构建最小可行 Harness](../09-驾驭工程/08-构建最小可行Harness.md)

**AGENTS.md**：跨工具的项目**常驻指令标准**（由 Linux 基金会 Agentic AI 基金会托管，30+ 工具支持），级联加载、控制在 50 行以内。→ 深入：[9.10 标准与 Skills](../09-驾驭工程/10-标准与Skills.md)

**Skill（技能）**：**可复用的能力包**（`SKILL.md` + 脚本 + 资源），按需加载；与 Tool 的区别是"Tool 是函数，Skill 是带流程与知识的技能包"。→ 深入：[9.10 标准与 Skills](../09-驾驭工程/10-标准与Skills.md)

**Spec（规格 / 规格驱动开发）**：**可执行的规格**，同时充当前馈（告诉 Agent 要什么）与验收依据（判定是否达成）。→ 深入：[9.10 标准与 Skills](../09-驾驭工程/10-标准与Skills.md)

**Rule（规则）**：头部常驻、始终生效的约束（如 `AGENTS.md`），与"按需加载"的 Skill、可执行的 Spec 构成三层区分。→ 深入：[9.7 Harness 工程方法论](../09-驾驭工程/07-Harness工程方法论.md)

**Plan Mode（计划模式）**：先产出计划、**只读不写**、待批准后再执行的工作模式；权限模式中对应 `plan` 档。→ 深入：[9.4 权限护栏与沙箱](../09-驾驭工程/04-权限护栏与沙箱.md)

**Sandbox（沙箱）**：授权之后的**执行隔离**（文件系统 / 网络 / 资源限制），保证"授权 ≠ 无限"。→ 深入：[9.4 权限护栏与沙箱](../09-驾驭工程/04-权限护栏与沙箱.md)

**Workspace（工作区）**：Agent 可读写文件、运行命令的隔离工作目录，是长时任务与文件系统级隔离的载体。→ 深入：[9.4 权限护栏与沙箱](../09-驾驭工程/04-权限护栏与沙箱.md)

**Subagent（子 Agent）**：为突破上下文窗口或并行探索而派生的下级 Agent；三种执行模型为 Fork（字节级副本）/ Teammate（文件邮箱）/ Worktree（git 隔离）。→ 深入：[9.6 子 Agent 编排与长时任务](../09-驾驭工程/06-子Agent编排与长时任务.md)

**Ralph Loop**：拦截模型的"退出"意图、**重注入提示词并强制在新上下文窗口中继续**的循环，用于对抗长任务中的"上下文焦虑"。→ 深入：[9.6 子 Agent 编排与长时任务](../09-驾驭工程/06-子Agent编排与长时任务.md)

**Model Routing（模型路由）**：按任务难度/成本把请求分派给不同模型（小模型处理简单任务），是降本核心手段。→ 深入：[6.3 成本控制](../06-高级主题/03-成本控制.md)

**Token 预算（Token Budget）**：为单次任务/单轮/单会话设定的 token 上限（常为"三重预算"：步数、token、时间），超限即终止，防失控与失控成本。→ 深入：[9.8 构建最小可行 Harness](../09-驾驭工程/08-构建最小可行Harness.md)

**Observation Masking（观察屏蔽）**：隐藏旧工具输出但保留工具调用记录，是五种上下文策略之一。→ 深入：[9.3 上下文工程与压缩](../09-驾驭工程/03-上下文工程与压缩.md)

## 四、RAG（检索增强生成）

**RAG（Retrieval-Augmented Generation，检索增强生成）**：先检索相关文档、再让 LLM 基于文档生成答案的范式，解决知识截止与私有数据问题。→ 深入：[5.1 RAG 原理](../05-RAG系统/01-RAG原理.md)

**Chunking（切分 / 分块）**：把长文档切成检索单元的过程；过碎会切断语义，过大则稀释信号，需配 overlap 或父子块。→ 深入：[5.2 文档处理](../05-RAG系统/02-文档处理.md)

**Embedding（嵌入）**：把文本映射为**高维向量**的过程/结果；检索质量高度依赖嵌入模型与维度一致性。→ 深入：[3.3 向量存储与检索](../03-LangChain实战/03-向量存储与检索.md)

**Vector Store（向量库）**：存储向量并支持相似度检索的系统（Chroma / FAISS / Qdrant / Pinecone / Milvus）。→ 深入：[5.3 向量数据库](../05-RAG系统/03-向量数据库.md)

**Hybrid Search（混合检索）**：融合**向量检索（语义）**与 **BM25（关键词精确匹配）**，用 RRF 等策略合并结果，弥补纯向量的短板。→ 深入：[5.4 优化策略](../05-RAG系统/04-优化策略.md)

**Rerank（重排）**：对初步召回的候选做**精细化二次排序**（如 cross-encoder），提升 Top-K 精度。→ 深入：[5.4 优化策略](../05-RAG系统/04-优化策略.md)

**HyDE（Hypothetical Document Embeddings，假设文档嵌入）**：先让 LLM 生成一个"假设答案"，再对该答案做嵌入检索，缓解"查询与文档用词不一致"的问题。→ 深入：[5.4 优化策略](../05-RAG系统/04-优化策略.md)

**MMR（Maximal Marginal Relevance，最大边际相关性）**：在相关性与多样性间折中，避免召回一堆高度相似的片段。→ 深入：[5.3 向量数据库](../05-RAG系统/03-向量数据库.md)

**Agentic RAG**：把改写、检索、重排、校验都变成 Agent **可自主调用的工具**，让它像人一样"按需检索、反复验证"。→ 深入：[5.1 RAG 原理](../05-RAG系统/01-RAG原理.md)

**GraphRAG**：用**知识图谱**组织实体与关系，解决朴素 RAG 的**多跳推理**与全局摘要问题。→ 深入：[5.1 RAG 原理](../05-RAG系统/01-RAG原理.md)

## 五、协议与标准

**MCP（Model Context Protocol）**：把工具/资源以**标准协议**暴露给任意 Agent 的开放标准；2026-07-28 规范引入 CIMD、MRTR、`Mcp-Method` 头与 `tools/list` 缓存。→ 深入：[8.10 MCP 协议完全指南](../08-生态与选型/协议标准/01-MCP协议完全指南.md)

**MCP Server / Client**：Server 提供工具/资源/提示；Client（宿主 Agent）连接并消费它们，实现"写一次工具，处处可用"。→ 深入：[8.10 MCP 协议完全指南](../08-生态与选型/协议标准/01-MCP协议完全指南.md)

**A2A（Agent2Agent Protocol）**：让**不同厂商的 Agent 互相通信与协作**的开放协议（Agent Card 描述能力、任务委托与状态同步）。→ 深入：[8.11 A2A 协议与互操作](../08-生态与选型/协议标准/02-A2A协议与互操作.md)

**Agent Card**：A2A 中描述一个 Agent 能力、端点与鉴权方式的元数据文档，是 Agent 间发现与互操作的前提。→ 深入：[8.11 A2A 协议与互操作](../08-生态与选型/协议标准/02-A2A协议与互操作.md)

**Transport（传输）**：MCP 的通信方式，常见 `stdio`（本地进程）与 `streamable_http`（远程服务）。→ 深入：[8.10 MCP 协议完全指南](../08-生态与选型/协议标准/01-MCP协议完全指南.md)

## 六、生产运维与评测

**LLM-judge（LLM 作为裁判）**：用 LLM 对输出打分/判定的评估方法；**仅作补充**，只判主观质量，且需结构化输出与人工校准。→ 深入：[6.2 评估与优化](../06-高级主题/02-评估与优化.md)

**Golden Set（黄金集 / 评测集）**：一组带标准答案的固定用例，用于回归对比——改了 Prompt/模型后判定"是变好还是变差"。→ 深入：[6.2 评估与优化](../06-高级主题/02-评估与优化.md)

**Programmatic Judgment（程序化判定）**：用确定性代码判定（格式对不对、工具调没调、有没有越权）；**能用程序判定的绝不用 LLM-judge**。→ 深入：[6.2 评估与优化](../06-高级主题/02-评估与优化.md)

**Regression（回归）**：新改动是否破坏了既有能力的系统性对比；生产用 CI 门禁自动阻断退化。→ 深入：[7.4 CI/CD 流水线](../07-生产部署/04-CICD流水线.md)

**Trace（追踪）**：一次请求跨模型/工具/节点的完整调用链记录，是定位"harness 问题还是模型问题"的第一手证据。→ 深入：[7.3 可观测性与监控](../07-生产部署/03-可观测性与监控.md)

**Span（跨度）**：Trace 中的一个环节（一次模型调用、一次工具执行），带属性与耗时，可嵌套成树。→ 深入：[7.3 可观测性与监控](../07-生产部署/03-可观测性与监控.md)

**OTel GenAI（OpenTelemetry GenAI 语义约定）**：为 LLM/Agent 定义的 `gen_ai.*` 标准属性，成为事实标准；换后端（Langfuse/LangSmith/Grafana）不改代码。→ 深入：[9.11 评测与可观测性](../09-驾驭工程/11-评测与可观测性.md)

**Observability（可观测性）**：用**日志 + 指标 + 追踪**三支柱回答"系统内部发生了什么"，生产 Agent 的必备能力。→ 深入：[7.3 可观测性与监控](../07-生产部署/03-可观测性与监控.md)

**Cost Attribution（成本归因）**：把 token 成本按用户/会话/功能维度拆解，定位成本黑洞。→ 深入：[6.3 成本控制](../06-高级主题/03-成本控制.md)

**Rate Limit（限流）**：限制单位时间请求数，防滥用与雪崩；服务端与模型端（429）两层都要处理。→ 深入：[7.1 API 服务部署](../07-生产部署/01-API服务部署.md)

**Prompt Injection（提示注入）**：攻击者通过输入诱导模型"自愿"违反系统提示；**能靠代码保证的事，绝不寄希望于模型自觉**。→ 深入：[6.4 安全与合规](../06-高级主题/04-安全与合规.md)

**PII（Personally Identifiable Information，个人可识别信息）**：需脱敏与合规处理的个人信息，常以中间件在出入模型前拦截。→ 深入：[6.4 安全与合规](../06-高级主题/04-安全与合规.md)
