## 二、项目定位

### 2.1 一句话定位

> **AgentLearn 是一份「从认知到生产」的开源 AI Agent 学习教程**——从"Agent 是什么"讲到"如何构建可托付的生产级 Agent"。

### 2.2 与其他教程的差异

| 维度  | 常见教程              | **AgentLearn**                |
| :-- | :---------------- | :---------------------------- |
| 覆盖面 | 只讲框架用法            | 框架 + 协议 + 生态 + **Harness 工程** |
| 时效性 | 停留在 2023–2024 API | 对齐 **2026 年 10 月**技术栈         |
| 深度  | 到"能跑起来"为止         | 一直讲到**生产就绪**（权限/验证/可观测）       |
| 代码  | 片段式、跑不通           | **可运行示例 + 离线自检**（无需 API Key）  |

### 2.3 目标读者

| 读者                 | 起点                  | 推荐入口             |
| :----------------- | :------------------ | :--------------- |
| 🟢 **AI 初学者**      | 会基础编程               | 第一部分 → 第二部分      |
| 🔵 **Python 开发者**  | 熟悉 Python，想入门 Agent | 第一部分 → 第三部分      |
| 🟠 **AI 工程师**      | 有 LLM 使用经验，想深入架构    | 第三 → 四 → 五 → 九部分 |
| 🔴 **技术负责人 / 架构师** | 关注落地、选型、合规          | 第六 → 七 → 八 → 九部分 |

### 2.4 前置要求

| 要求         | 说明                                             |
| :--------- | :--------------------------------------------- |
| 🐍 Python  | **3.12+**（会用类型注解、`async`）                      |
| 📦 包管理器    | [uv](https://docs.astral.sh/uv/) >= 0.5.0      |
| 🔑 API Key | OpenAI / Anthropic / Gemini / DeepSeek / 通义 任一 |
| 🧠 心智准备    | 第九部分需要理解"机制优于提示词"的工程思维                         |

### 5.1 快速上手（2 周 · 约 20 小时）

> 适合：想尽快跑通一个能用的 Agent 的开发者。

```text
第 1 周   1.1 → 1.2 → 1.3 → 3.1 → 3.2 → 3.4
          （导论 → 环境 → 第一个 Agent → create_agent → 工具 → 聊天 Agent）
```

## 七、文档规范

> 全站文档必须遵循以下规范，保证一致性与可维护性。

### 7.1 五段式结构（正文章节强制）

章节骨架（每章必须齐备，链接路径以章节所在目录为基准）：

<!-- doc-check: skip -->

```text
# 章节标题

> 📅 更新至 YYYY-MM · 技术栈基线见 [教程大纲](../教程大纲.md)

## 📖 导读 / 本章目标      ← 一句话结论 + 前置阅读 + 本章你将学到
## 一、二、三……           ← 正文（每节尽量配表格/图示/代码）
## 本章小结               ← 一张"要点 → 说明"表
## 📝 课后练习             ← 3–4 题，分基础/进阶/挑战
```

### 7.2 代码规范

| 规则         | 说明                                                       |
| :--------- | :------------------------------------------------------- |
| **可运行优先**  | 能跑通的代码要标注文件路径；跑不通的要注明"示意"                                |
| **版本对齐**   | 一律使用 v1 语法；禁止 `AgentExecutor`、`create_react_agent`（旧路径）等 |
| **模型名统一**  | 教程统一用 `gpt-5.5`；示例代码通过 `.env` 注入，不硬编码                    |
| **不硬编码密钥** | 一律从环境变量读取                                                |
| **完整导入**   | 代码片段必须包含所需 `import`，避免"未定义"类错误                           |

### 7.3 交叉引用规范

| 规则            | 说明                                     |
| :------------ | :------------------------------------- |
| **相对路径**      | 一律使用相对路径（`../02-核心概念/03-Agent核心架构.md`） |
| **不引用不存在的文件** | 引用 `examples/` 前先确认目录存在                |
| **章节号一致**     | 正文提到的章节号必须与 `_sidebar.md` 一致           |

### 7.4 版本与日期

| 项          | 规则                                                              |
| :--------- | :-------------------------------------------------------------- |
| **技术栈基线**  | 以 `pyproject.toml` 为准（见附录 A）                                    |
| **更新日期**   | 每章顶部**统一**标注 `> 📅 更新至 YYYY-MM · 技术栈基线见 [教程大纲]`（紧跟 H1 标题，空行分隔） |
| **不确定性标注** | 快速迭代的工具/API 标注"**以官方文档为准**"                                     |

### 7.5 自动校验（CI）

> 教程会"腐烂"——链接会失效、代码会过时。本仓库用脚本把腐烂挡在提交之前。

| 检查         | 命令                                              | 作用                                         |
| :--------- | :---------------------------------------------- | :----------------------------------------- |
| **链接校验**   | `python scripts/check_docs.py --links`          | 扫描全站相对链接，报告指向不存在文件的死链                      |
| **代码块语法**  | `python scripts/check_docs.py --code`           | 抽取 Markdown 中的 Python 代码块并 `py_compile` 校验 |
| **结构校验**   | `python scripts/check_docs.py --structure`      | 检查正文章节是否具备"导读 / 小结 / 练习"五段式                |

### 附录 B：核心术语表

| 术语                | 一句话解释                                     |
| :---------------- | :---------------------------------------- |
| **Agent**         | 一种涌现行为：有目标、会用工具、能自我纠正                     |
| **Harness**       | 模型之外的一切——产生 Agent 行为的"机器"                 |
| **TAO / ReAct**   | Thought-Action-Observation 循环，Agent 的基本心跳 |
| **Context Rot**   | 上下文变长导致的性能退化（非"窗口不够大"）                    |
| **Compaction**    | 接近上限时把历史总结成摘要的压缩策略                        |
| **deny-first**    | 权限判定顺序：先查 deny，deny 永远覆盖 allow            |
| **Guardrail**     | 输入/输出/工具三级可执行检查                           |
| **Tripwire**      | 护栏触发时的"熔断"信号，触发即停机                        |
| **Back-pressure** | 让失败后果立刻反馈回模型，迫使自我修正                       |
| **Stop Gate**     | Agent 准备结束时的确定性验证门                        |
| **MVH**           | Minimum Viable Harness，最小可行 Harness       |
| **AGENTS.md**     | 跨工具的项目常驻指令标准（Linux 基金会托管）                 |
| **Skill**         | 按需加载的可复用能力包（渐进式披露）                        |
| **Spec**          | 可执行的规格，同时充当前馈与验收依据                        |

### 附录 C：三张速查表

**C1. Harness vs Framework vs 低代码平台**

| 维度   | Framework（库）                   | Agent Harness                 | 低代码平台    |
| :--- | :----------------------------- | :---------------------------- | :------- |
| 给你什么 | 积木                             | 整机                            | 流水线      |
| 决策者  | 架构师 + 工程团队                     | 开发者 / DevOps                  | 业务方      |
| 灵活性  | 最高                             | 中高                            | 低        |
| 代表   | LangGraph、LlamaIndex Workflows | `dsh`、Deep Agents、Claude Code | Dify、n8n |

**C2. 四档验证强度**

|       档位      |  强制力  |  成本 | 场景       |
| :-----------: | :---: | :-: | :------- |
|      内联提示     |   低   |  极低 | 原型       |
|   `/goal` 条件  |   中   |  低  | 有明确验收标准  |
| **Stop Hook** | **高** |  中  | **生产默认** |
|   对抗性子 Agent  |   最高  |  高  | 高风险改动    |

**C3. 五类失败模式 → Harness 解法**

| 失败模式  | 解法                          |
| :---- | :-------------------------- |
| 上下文腐化 | 压缩 / 剪枝 / 进度文件 / 子 Agent 隔离 |
| 工具爆炸  | 按阶段动态收窄工具集                  |
| 静默失败  | 每次工具调用后结构化输出校验              |
| 无限循环  | 重试上限 + 退避 + 循环检测            |
| 状态损坏  | 恢复时校验前置条件                   |
