# 1.2 开发环境搭建 —— 用 uv 构建可复现的 Agent 开发环境

> 📅 更新至 2026-10 · 技术栈基线见 [教程大纲](../教程大纲.md)

## 📖 导读

> **一句话结论**：Agent 开发环境的正确姿势是 **Python 3.12+ + uv + `.env`**——uv 负责"依赖可复现"，`.env` 负责"配置可切换"，二者配合能让你的环境在 macOS / Windows / Linux 上行为一致。

- **前置阅读**：[1.1 AI Agent 导论](./01-AI-Agent导论.md)。
- **本章你将学到**：
  1. 三平台安装 Python 3.12+ 与 `uv` 的正确方式；
  2. **完整的 `uv` 工作流**（`uv sync` / `uv add` / `uv run` / `uv lock`）；
  3. `.env` 配置约定（`LLM_MODEL_NAME` / `LLM_API_KEY` / `LLM_BASE_URL` 及回退规则）；
  4. Windows / macOS / Linux 的关键差异；
  5. 常见安装报错的排查方法。

## 一、环境概览

| 组件 | 版本要求 | 用途 |
|------|----------|------|
| Python | **≥ 3.12** | Agent 开发语言（3.10/3.11 已不在本教程支持范围） |
| uv | 最新版 | Python 包管理器 + 虚拟环境管理 |
| Git | ≥ 2.0 | 代码版本管理 |
| VS Code | 最新版（推荐） | 编辑器 |
| LLM API Key | 有效 | 调用大模型 |

### 1.1 为什么用 uv 而不是 pip？

| 对比项 | pip / venv | uv |
|--------|-----------|-----|
| **速度** | 较慢 | **快 10–100 倍**（并行下载 + 全局缓存） |
| **依赖解析** | 标准 | 更快更准，冲突可复现 |
| **虚拟环境** | 需手动 `python -m venv` | **内置**，自动创建 `.venv` |
| **锁文件** | 需 pip-tools | **原生 `uv.lock`**，团队可复现 |
| **Python 版本** | 需自行安装 | `uv python install` 一键装 |
| **运行脚本** | 先激活 venv | `uv run xxx.py` 免激活 |

> 💡 **可复现性**是 uv 最大的价值：`pyproject.toml` 声明"要什么"，`uv.lock` 锁定"装了什么版本"，任何人 `uv sync` 后环境一致。

## 二、安装 Python 3.12+

### 2.1 三平台安装方式

| 平台 | 推荐方式 | 命令 / 步骤 |
|------|----------|-------------|
| **macOS** | Homebrew | `brew install python@3.12` |
| **macOS** | uv 托管（最省事） | `uv python install 3.12`（见 2.2） |
| **Windows** | 官网安装包 | 下载 3.12.x，**务必勾选 "Add Python to PATH"** |
| **Windows** | uv 托管 | `uv python install 3.12` |
| **Linux** | 发行版包 | `sudo apt install python3.12 python3.12-venv` |
| **Linux** | pyenv（精确版本） | `pyenv install 3.12.8` |

### 2.2 推荐：用 uv 托管 Python（跨平台一致）

uv 可以自己下载并管理 Python，**无需系统预装**，最适合新手：

```bash
# 安装 Python 3.12（uv 会下载到自己的目录，不污染系统）
uv python install 3.12

# 查看 uv 管理下的所有 Python
uv python list
```

### 2.3 前置检查

```bash
python --version      # Windows 用 python；macOS/Linux 可能需 python3
git --version
```

> ⚠️ **macOS 注意**：系统自带的 `/usr/bin/python3` 版本可能偏旧，且**不建议**用它跑项目；请用 Homebrew 或 uv 安装的版本。

## 三、安装 uv

### 3.1 macOS / Linux

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh

# 让当前终端生效（或直接重开终端）
source ~/.bashrc    # bash
# source ~/.zshrc   # zsh（macOS 默认）

uv --version        # 预期输出: uv x.y.z
```

### 3.2 Windows（PowerShell）

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

**备选方式**（若无权限或网络受限）：

```powershell
pip install uv          # 已装 pip 时的最简方式
winget install --id=astral-sh.uv -e   # 或使用 winget
```

安装后**重开一个终端**，验证：

```powershell
uv --version
```

> 💡 若提示 `uv: command not found`，多为 PATH 未刷新，见 [七、常见报错排查](#七常见报错排查)。

## 四、uv 完整工作流（核心）

### 4.1 命令速查表

| 命令 | 作用 | 何时用 |
|------|------|--------|
| `uv init` | 初始化项目（生成 `pyproject.toml`） | 从零新建项目 |
| `uv python install 3.12` | 安装指定 Python | 首次搭建 |
| `uv sync` | **按 lock 同步依赖并创建 `.venv`** | 拉取项目后第一步 |
| `uv add <pkg>` | 添加依赖并写入 `pyproject.toml` + `uv.lock` | 引入新库 |
| `uv remove <pkg>` | 移除依赖 | 清理 |
| `uv lock` | 仅重新解析并更新 `uv.lock` | 改了依赖声明后 |
| `uv run <script.py>` | **在项目环境中运行脚本**（自动同步） | 日常运行 |
| `uv pip list` | 列出已安装包 | 排查依赖 |
| `uv self update` | 升级 uv 自身 | 保持最新 |

### 4.2 两种工作模式

**模式 A：克隆现成项目（本教程场景）**

```bash
git clone https://gitcode.com/mininote/AgentLearn.git
cd AgentLearn
uv sync          # 读取 pyproject.toml + uv.lock，创建 .venv 并装齐依赖
```

**模式 B：从零新建项目**

```bash
uv init my-agent
cd my-agent
uv add langchain langchain-openai langgraph
uv run main.py
```

### 4.3 `uv run`：免激活虚拟环境

使用 uv 后，**绝大多数场景无需手动激活 `.venv`**，直接用 `uv run` 即可：

```bash
uv run examples/01-hello-agent/main.py
```

如果你更习惯"激活后直接用 `python`"：

| 平台 | 激活命令 |
|------|----------|
| macOS / Linux | `source .venv/bin/activate` |
| Windows (cmd) | `.venv\Scripts\activate` |
| Windows (PowerShell) | `.venv\Scripts\Activate.ps1` |

激活成功后提示符会出现 `(.venv)` 前缀。

### 4.4 国内网络加速

若下载缓慢，配置清华镜像（`pyproject.toml` 中已内置该源，一般无需再设）：

```bash
# 临时（单次）
uv sync --index-url https://pypi.tuna.tsinghua.edu.cn/simple

# 持久（环境变量）
export UV_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple   # macOS/Linux
# Windows PowerShell:  $env:UV_INDEX_URL = "https://pypi.tuna.tsinghua.edu.cn/simple"
```

## 六、配置 `.env`

### 6.1 创建 `.env`

```bash
cp .env.example .env          # macOS / Linux
copy .env.example .env        # Windows (cmd)
Copy-Item .env.example .env   # Windows (PowerShell)
```

### 6.2 填写配置

```env
# ---------- 教程统一约定（推荐）----------
LLM_API_KEY=sk-your-api-key-here
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL_NAME=gpt-5.5

# ---------- 可观测性（可选）----------
LANGSMITH_TRACING=false
LANGSMITH_PROJECT=agentlearn
```

### 6.3 变量读取约定（重要）

本教程所有示例统一按下面的规则读取配置，**缺省时自动回退到 `langchain-openai` 原生变量**：

```python
import os
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model=os.getenv("LLM_MODEL_NAME", "gpt-5.5"),
    api_key=os.getenv("LLM_API_KEY") or os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("LLM_BASE_URL") or os.getenv("OPENAI_API_BASE"),
)
```

| 变量 | 是否必需 | 缺省回退 | 说明 |
|------|----------|----------|------|
| `LLM_MODEL_NAME` | 否 | `gpt-5.5` | 模型名 |
| `LLM_API_KEY` | 是 | `OPENAI_API_KEY` | API 密钥 |
| `LLM_BASE_URL` | 否 | `OPENAI_API_BASE` | 兼容端点（需以 `/v1` 结尾） |

> ⚠️ **注意**：`ChatOpenAI` 原生只读 `OPENAI_API_KEY` / `OPENAI_API_BASE`，**不会自动读 `LLM_*`**；因此代码里必须显式传入（如上）。
>
> 🔐 **安全提醒**：`.env` 已被 `.gitignore` 排除，**切勿把真实 Key 提交到 Git**。

### 6.4 常见模型服务商

| 服务商 | Base URL 示例 | 备注 |
|--------|---------------|------|
| OpenAI | `https://api.openai.com/v1` | 官方，需海外网络 |
| Anthropic | `https://api.anthropic.com` | 用 `langchain-anthropic` |
| DeepSeek | `https://api.deepseek.com/v1` | 国产，性价比高 |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | OpenAI 兼容 |

## 七、常见报错排查

### ❌ `python: command not found` / `python3: command not found`

```bash
# macOS / Linux 优先用 python3；或用 uv 托管的解释器
uv run python --version

# Windows：重装 Python 并勾选 "Add Python to PATH"，或改用 uv
```

### ❌ `uv: command not found`

```bash
# macOS/Linux：重开终端，或手动加 PATH
export PATH="$HOME/.local/bin:$PATH"

# Windows：重开 PowerShell；若仍失败，改用 pip install uv
```

### ❌ `ModuleNotFoundError: No module named 'langchain_openai'`

原因：**没装依赖，或用了系统 Python 而非项目 `.venv`**。

```bash
uv sync                       # 确保依赖已装
uv run python examples/01-hello-agent/main.py   # 用项目环境运行
```

### ❌ `AuthenticationError` / `401`

排查顺序：

1. `.env` 文件是否存在（注意不要变成 `.env.txt`）；
2. `LLM_API_KEY` 是否完整、**未被引号包裹**；
3. Key 是否还有余额；
4. `LLM_BASE_URL` 是否正确（结尾 `/v1`）；
5. 代码是否调用了 `load_dotenv()`。

### ❌ `httpx.ConnectError` / 连接超时

- 国内直连 OpenAI 官方 API 通常不可达，请改用国内兼容服务，或配置代理；
- 用 `curl` 快速验证端点连通性：

```bash
curl -X POST "$LLM_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $LLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-5.5","messages":[{"role":"user","content":"hi"}]}'
```

### ❌ Windows 上 `Activate.ps1 ... 因为在此系统上禁止运行脚本`

```powershell
# 仅对当前用户放开脚本执行（无需管理员）
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

## 本章小结

| 步骤 | 要做什么 | 验证命令 |
|------|----------|----------|
| 1️⃣ | 安装 Python 3.12+ | `uv run python --version` |
| 2️⃣ | 安装 uv | `uv --version` |
| 3️⃣ | 克隆项目 | `git clone ...` |
| 4️⃣ | 同步依赖 | `uv sync` |
| 5️⃣ | 运行脚本（免激活） | `uv run <script.py>` |
| 6️⃣ | 配置 API Key | 编辑 `.env`（`LLM_*` 三件套） |
| 7️⃣ | IDE 配置 | 选择 `.venv` 解释器 |

| 要点 | 说明 |
|------|------|
| **uv 的价值** | 依赖可复现（`uv.lock`）+ 极速 + 内置虚拟环境 |
| **`.env` 约定** | `LLM_MODEL_NAME` / `LLM_API_KEY` / `LLM_BASE_URL`，缺省回退 `OPENAI_*` |
| **运行方式** | 首选 `uv run`，无需手动激活 |
| **三平台差异** | 激活脚本、PATH、镜像设置方式不同，其余一致 |

**进阶**
2. 用 `uv init` 从零新建一个空项目，`uv add langchain-openai`，写一个 5 行的脚本打印 `llm.invoke("你好").content`，用 `uv run` 运行它。

**挑战**
4. 把环境变量从 `LLM_*` 切换到 `OPENAI_*`（只改 `.env`，不改代码），验证回退逻辑生效；再说明如果要同时维护两套 Key（如 OpenAI + DeepSeek），代码应该怎么改。
