## 一、前置知识铺垫

在深入 Agent 之前，先统一几个基础概念（后续章节会反复用到）：

| 概念 | 说明 |
|------|------|
| **LLM（大语言模型）** | 如 GPT-5.5、Claude Sonnet 4.6、Gemini 3、DeepSeek V4 等，负责理解与生成语言，是 Agent 的"大脑" |
| **Token（令牌）** | LLM 的输入/输出计量单位，1 个汉字约 2–3 tokens，直接影响成本与上下文长度 |
| **Prompt（提示词）** | 送入模型的指令与信息，决定输出的方向（详见 [2.1 Prompt 与上下文工程](../02-核心概念/01-Prompt与上下文工程.md)） |
| **Tool（工具）** | Agent 可调用的外部能力：搜索、计算、查数据库、发邮件、执行代码…… |
| **上下文窗口** | 一次调用能容纳的最大 token 数（2026 年主流模型约 128K–1M） |

> 💡 如果这些概念你已经熟悉，可直接跳到「二、什么是 AI Agent」。

## 二、什么是 AI Agent？

**AI Agent（人工智能代理）** 是一种能 **自主感知环境 → 理解分析 → 决策规划 → 执行行动** 的智能软件实体。它的核心特征不是"能聊天"，而是"**能做事**"，且这个"做事"的过程由 LLM 在运行时动态决定。

### 2.1 Agent 工作循环

```
                    ┌───────────────────┐
                    │    感知环境        │  用户输入 / 工具结果 / 系统状态
                    └────────┬──────────┘
                             ▼
                    ┌───────────────────┐
                    │    理解与分析      │  拆解任务 / 识别意图
                    └────────┬──────────┘
                             ▼
                    ┌───────────────────┐
                    │    决策与规划      │  选择策略 / 挑选工具
                    └────────┬──────────┘
                             ▼
                    ┌───────────────────┐
                    │    执行行动        │  调用工具 / 生成回复
                    └────────┬──────────┘
                             │
                    ┌────────┴────────┐
                    ▼                 ▼
                任务完成          继续下一轮（回到"感知"）
```

这个循环会持续进行，直到 Agent 认为目标达成、达到最大步数上限，或遇到无法处理的异常。

### 2.2 一个最小可运行示例

在 LangChain v1 中，这个循环被封装成一个函数 `create_agent`（[1.3 第一个 Agent](./03-第一个Agent.md) 会逐行讲解）：

```python
from langchain.agents import create_agent
from langchain.tools import tool


@tool
def get_weather(city: str) -> str:
    """查询指定城市的天气。"""
    return f"{city} 今天晴，25℃。"


agent = create_agent(
    model="gpt-5.5",
    tools=[get_weather],
    system_prompt="你是一个出行助手，用中文回答。",
)

result = agent.invoke({"messages": [{"role": "user", "content": "北京要带伞吗？"}]})
print(result["messages"][-1].content)
```

短短几行，模型就会自主判断"需要调用天气工具 → 拿到结果 → 组织回答"。

## 三、Agent vs Chatbot vs Workflow（重点）

这是初学者最容易混淆的一组概念。**三者的区别不在"用不用 LLM"，而在"谁决定下一步做什么"。**

| 维度 | Chatbot（聊天机器人） | Workflow（工作流） | AI Agent |
|------|----------------------|--------------------|----------|
| **控制流** | 一问一答，无步骤 | 由开发者**预先写死**（DAG/流程） | 由 **LLM 运行时动态决定** |
| **决策者** | 无（只生成文本） | 开发者 | LLM |
| **能否调用工具** | ❌ 通常不能 | ✅ 但路径固定 | ✅ 自主选择工具与顺序 |
| **多步任务** | ❌ 不擅长 | ✅ 确定的多步 | ✅ 不确定的多步 |
| **可预测性** | 高 | 高 | 中（需要护栏） |
| **成本/时延** | 低 | 低 | 较高（多轮推理） |
| **典型实现** | `llm.invoke()` 循环 | LCEL / LangGraph 固定图 | `create_agent` / LangGraph 动态图 |

**一句话判断标准**：

- **Chatbot**：只会"说"，不会"做"。
- **Workflow**：会"做"，但**每一步都是你写好的**。
- **Agent**：会"做"，且**下一步做什么由模型当场决定**。

> 📌 一个更锋利的判断法：**如果去掉 LLM 系统还能照常运行，那它是 Workflow；如果去掉 LLM 就瘫痪，那它才可能是 Agent。**

**三者的关系不是替代，而是协作**：生产系统里通常是"**Agent 决策 + Workflow 执行**"——用 Agent 处理不确定的开环环节，把确定性的闭环步骤固化为 Workflow（LCEL/LangGraph）。这也是 [2.2 Chain 模式详解](../02-核心概念/02-Chain模式详解.md) 与 [2.3 Agent 核心架构](../02-核心概念/03-Agent核心架构.md) 反复强调的分工。

## 四、Agent 的四大核心能力

| 能力 | 英文 | 具体表现 |
|------|------|----------|
| **感知** | Perception | 读取文本、结构化数据、多模态输入（图片/音频）、系统状态 |
| **推理与规划** | Reasoning & Planning | 意图识别、任务拆解、路径规划、自我反思 |
| **行动** | Action | 调用工具、生成内容、操作文件/API/数据库、多轮澄清 |
| **记忆** | Memory | 短期（会话上下文）+ 长期（跨会话画像/经验），详见 [2.4 记忆机制](../02-核心概念/04-记忆机制.md) |

### 4.1 推理与规划：Agent 的"智能"所在

- **意图识别**：用户说"有点冷" → 意图是调高空调；
- **任务拆解**：把"写一份市场报告"拆成"检索 → 归纳 → 成文"；
- **路径规划**：先搜索后总结，还是先查库后计算；
- **自我反思**：发现上一步结果不对，主动换一种方法重试。

### 4.2 行动：从"回答"到"解决"

行动能力是 Agent 与传统问答最本质的差别。它可以是**调用工具**（搜索网页、执行代码、查数据库）、**生成产物**（报告、图表、代码），也可以是**改变外部系统状态**（发邮件、建工单、控制设备）。

## 五、发展简史与 2026 生态速览

### 5.1 关键里程碑

| 时间 | 事件 | 影响 |
|------|------|------|
| 2017 | Google 发表《Attention Is All You Need》 | Transformer 取代 RNN，奠定 LLM 基础 |
| 2022.11 | ChatGPT 发布 | LLM 走向大众，"提示工程"兴起 |
| 2023.03 | LangChain 发布 Agent 模块 | Agent 开发开始标准化 |
| 2023.04 | AutoGPT 开源 | "自主 Agent"概念爆发 |
| 2024 | 多 Agent 框架（CrewAI、AutoGen）成熟 | 从单 Agent 走向 Agent 团队 |
| **2025.10** | **LangChain v1 / LangGraph v1 正式 GA** | **`create_agent` + Middleware，框架进入生产就绪** |
| 2025.11 | MCP 成为工具调用事实标准 | 跨厂商工具生态被统一 |
| 2026.04 | Microsoft Agent Framework 1.0 GA | AutoGen + Semantic Kernel 合并统一 |
| 2026.07 | MCP 无状态核心发布 | Agent 通信可像普通 HTTP 一样水平扩展 |
| 2026.09 | A2A v1.0 GA | Agent 进入跨组织互操作时代 |

### 5.2 2026 年的关键词：协议化与互联互通

如果说 2023–2024 年在探索"Agent 能做什么"、2025 年在解决"怎么构建 Agent"，那么 **2026 年是在解决"Agent 之间怎么互联"**。两大开放协议重塑了行业：

| 协议 | 主导方 | 解决的问题 | 类比 |
|------|--------|-----------|------|
| **MCP**（Model Context Protocol） | Anthropic 发起，全行业共建 | Agent ↔ 工具/数据源 的标准连接 | AI 世界的 **USB-C** |
| **A2A**（Agent-to-Agent） | Google 发起，多厂商支持 | Agent ↔ Agent 的跨组织协作 | Agent 世界的 **HTTP** |

这意味着：

- **工具不再需要为每个框架重复适配**——写一个 MCP Server，所有支持 MCP 的 Agent 都能用；
- **不同公司、不同框架的 Agent 可以互相调用**——通过 A2A 交换任务与结果；
- **框架选型不再是"押注"**——底层协议统一后，上层框架可随时替换。

> 📌 本教程第八部分会深入讲解 [MCP 协议完全指南](../08-生态与选型/协议标准/01-MCP协议完全指南.md) 与 [A2A 协议与互操作](../08-生态与选型/协议标准/02-A2A协议与互操作.md)。

### 5.3 本教程的技术栈基线（2026-10）

本教程统一使用以下版本，全部代码均基于此验证：

| 组件 | 版本 | 用途 |
|------|------|------|
| Python | **≥ 3.12** | 运行语言 |
| `uv` | 最新版 | 包管理与虚拟环境 |
| `langchain` | **≥ 1.4.5** | Agent 构建（`create_agent`） |
| `langchain-core` | **≥ 1.6.10** | 消息、Runnable、工具等基础抽象 |
| `langchain-openai` | **≥ 1.7.1** | OpenAI 兼容模型接入 |
| `langchain-anthropic` | **≥ 1.7.6** | Claude 接入 |
| `langgraph` | **≥ 1.2.15** | 底层运行时（持久化、流式、人机协同） |

1. **Agent 的唯一入口是 `from langchain.agents import create_agent`**；旧版的 `AgentExecutor` / `create_react_agent` 已不再是推荐写法。
2. **记忆/持久化统一用 `from langgraph.checkpoint.memory import InMemorySaver`**（新路径），不再使用 `langgraph.checkpoint.MemorySaver`。

## 七、常见认知误区

| 误区 | 正解 |
|------|------|
| "Agent 就是聊天机器人" | Agent 的核心是**自主行动**，聊天只是交互形式之一 |
| "有 LLM 就有 Agent" | LLM 是大脑，Agent 还需要工具、记忆、护栏等完整系统 |
| "Agent 可以完全自主运行" | 关键决策节点仍需**人工监督**（Human-in-the-Loop） |
| "开发 Agent 很难" | 借助 LangChain v1 的 `create_agent`，入门门槛已很低 |
| "Agent 永远不会出错" | Agent 会犯错，必须设计**容错与验证机制** |
| "Workflow 过时了" | 确定性流程用 Workflow 更省、更稳；Agent 与 Workflow 是协作关系 |
