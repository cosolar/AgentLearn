# 6.3 成本控制策略 —— 花最少的钱，做最好的 Agent

> 📅 更新至 2026-10 · 技术栈基线见 [教程大纲](../教程大纲.md)

## 📖 导读

> **LLM API 按 Token 计费。一个不加控制的 Agent，一天可能烧掉几百美元。**

成本控制是 Agent 从"实验"走向"生产"的必修课。核心不是"少用"，而是**在质量和成本之间找到平衡点**：把贵的模型用在刀刃上，把重复的计算缓存起来，把每一分钱都归因到具体功能上。本节给出 token 预算、缓存、模型路由、成本归因四件套，并维护**全教程唯一的价格表**。

## 一、成本构成

### 1.1 计费模型

```text
单次调用费用 = 输入 Token 数 × 输入单价 + 输出 Token 数 × 输出单价

示例（旗舰模型量级）：
输入：500 tokens × $0.00125 / 1K = $0.000625
输出：200 tokens × $0.010   / 1K = $0.002
合计：≈ $0.0026
```

> 💡 **输出通常比输入贵 5–10 倍**。控制输出长度往往比压缩输入更划算。

### 1.2 价格表（全教程单一数据源）

> ⚠️ **下表为量级示意，实际价格随厂商调整而变动，请以各厂商官网为准。** 本教程所有章节的成本计算均引用此处，不另行维护。

| 模型 | 输入（$/1K tokens） | 输出（$/1K tokens） | 相对成本 |
|------|--------------------|--------------------|----------|
| **gpt-5.5**（旗舰） | ~0.00125 | ~0.010 | 中高 |
| **gpt-5-mini** | ~0.00025 | ~0.002 | ⭐ 低 |
| **gemini-3-flash** | ~0.0001 | ~0.0004 | ⭐ 极低 |
| **deepseek-v4** | ~0.0003 | ~0.0012 | ⭐ 低 |
| **text-embedding-3-small** | ~0.00002 | — | 极低 |

> 💡 **小模型（mini / flash）通常比旗舰便宜 10–50 倍**，简单任务优先使用。

## 二、计量与归因

### 2.1 Token 计量与成本计算器

```python
"""Token 计量与成本计算：引用全教程唯一价格表"""
from __future__ import annotations

from dataclasses import dataclass, field


class CostCalculator:
    """Token / 成本计算器（价格表为全教程单一数据源）"""

    # 单位：每 1K tokens 美元；量为量级示意，实际以厂商官网为准。
    MODEL_PRICING: dict[str, dict[str, float]] = {
        "gpt-5.5": {"input": 0.00125, "output": 0.010},
        "gpt-5-mini": {"input": 0.00025, "output": 0.002},
        "gemini-3-flash": {"input": 0.0001, "output": 0.0004},
        "deepseek-v4": {"input": 0.0003, "output": 0.0012},
        "text-embedding-3-small": {"input": 0.00002, "output": 0.0},
    }

    def __init__(self, model: str = "gpt-5.5"):
        self.model = model
        self.pricing = self.MODEL_PRICING.get(model, {"input": 0.01, "output": 0.03})

    @staticmethod
    def count_tokens(text: str, model: str = "gpt-5.5") -> int:
        """优先用 tiktoken 精确计数，失败则按字符估算"""
        try:
            import tiktoken

            encoding = tiktoken.encoding_for_model(model)
            return len(encoding.encode(text))
        except Exception:
            # 粗略估算：中文约 1 token/字，英文约 0.25 token/字符
            return int(len(text) * 0.6) + 1

    def cost_of(self, input_tokens: int, output_tokens: int) -> float:
        """按 token 数计算成本（美元）"""
        return (
            input_tokens / 1000 * self.pricing["input"]
            + output_tokens / 1000 * self.pricing["output"]
        )

    def cost_of_text(self, input_text: str, output_text: str) -> dict:
        """按文本计算成本，返回明细"""
        in_tok = self.count_tokens(input_text, self.model)
        out_tok = self.count_tokens(output_text, self.model)
        total = self.cost_of(in_tok, out_tok)
        return {
            "model": self.model,
            "input_tokens": in_tok,
            "output_tokens": out_tok,
            "total_tokens": in_tok + out_tok,
            "cost_usd": round(total, 6),
        }

    def estimate_monthly(
        self, daily_queries: int, avg_input_tokens: int, avg_output_tokens: int
    ) -> dict:
        """估算月成本"""
        per_query = self.cost_of(avg_input_tokens, avg_output_tokens)
        monthly = per_query * daily_queries * 30
        return {
            "per_query_usd": round(per_query, 6),
            "daily_usd": round(per_query * daily_queries, 2),
            "monthly_usd": round(monthly, 2),
            "annual_usd": round(monthly * 12, 2),
        }


if __name__ == "__main__":
    calc = CostCalculator("gpt-5.5")
    print(calc.cost_of_text("你是一个助手。用户：什么是 RAG？", "RAG 是检索增强生成……"))
    print(calc.estimate_monthly(daily_queries=1000, avg_input_tokens=1000, avg_output_tokens=500))
```

### 2.2 成本归因：把账单拆到功能维度

只看"总花费"没用，要知道**钱花在哪个功能、哪个租户、哪个模型**上。

```python
"""成本归因：按 租户 / 功能 / 模型 维度聚合"""
from __future__ import annotations

from collections import defaultdict
from dataclasses import dataclass, field


@dataclass
class UsageRecord:
    """一次 LLM 调用的用量记录"""

    tenant: str
    feature: str
    model: str
    input_tokens: int
    output_tokens: int
    cost_usd: float


@dataclass
class CostAttributor:
    """成本归因器：多维聚合，支持按维度出账"""

    calculator: CostCalculator = field(default_factory=CostCalculator)
    records: list[UsageRecord] = field(default_factory=list)

    def record(
        self, tenant: str, feature: str, model: str, input_tokens: int, output_tokens: int
    ) -> UsageRecord:
        """记录一次调用并归因"""
        cost = self.calculator.MODEL_PRICING.get(model, {"input": 0.01, "output": 0.03})
        amount = input_tokens / 1000 * cost["input"] + output_tokens / 1000 * cost["output"]
        rec = UsageRecord(tenant, feature, model, input_tokens, output_tokens, round(amount, 6))
        self.records.append(rec)
        return rec

    def _aggregate(self, key: str) -> dict[str, float]:
        buckets: dict[str, float] = defaultdict(float)
        for rec in self.records:
            buckets[getattr(rec, key)] += rec.cost_usd
        return {k: round(v, 4) for k, v in sorted(buckets.items(), key=lambda x: -x[1])}

    def by_tenant(self) -> dict[str, float]:
        return self._aggregate("tenant")

    def by_feature(self) -> dict[str, float]:
        return self._aggregate("feature")

    def by_model(self) -> dict[str, float]:
        return self._aggregate("model")

    @property
    def total(self) -> float:
        return round(sum(r.cost_usd for r in self.records), 4)


if __name__ == "__main__":
    attributor = CostAttributor()
    attributor.record("tenant-a", "chat", "gpt-5.5", 1200, 400)
    attributor.record("tenant-a", "summarize", "gpt-5-mini", 3000, 300)
    attributor.record("tenant-b", "chat", "gpt-5.5", 900, 350)
    print("按租户:", attributor.by_tenant())
    print("按功能:", attributor.by_feature())
    print("总计:", attributor.total)
```

## 三、成本优化四件套

### 3.1 Token 预算：给每次请求装"电表"

```python
"""Token 预算：超预算即降级或拒绝，避免单次请求失控"""
from __future__ import annotations

from dataclasses import dataclass


@dataclass
class BudgetGuard:
    """按请求 / 按天控制 token 预算"""

    max_tokens_per_request: int = 8000
    max_tokens_per_day: int = 2_000_000

    def __post_init__(self) -> None:
        self._used_today = 0

    def check(self, estimated_tokens: int) -> tuple[bool, str]:
        """检查是否超预算，返回 (是否放行, 原因)"""
        if estimated_tokens > self.max_tokens_per_request:
            return False, f"单次请求 {estimated_tokens} 超过上限 {self.max_tokens_per_request}"
        if self._used_today + estimated_tokens > self.max_tokens_per_day:
            return False, "当日预算已用尽"
        return True, "ok"

    def consume(self, tokens: int) -> None:
        self._used_today += tokens

    @property
    def used_today(self) -> int:
        return self._used_today
```

> 💡 预算的三道闸：**单请求上限 → 单用户日限额 → 全局日限额**。任何一道触发都应优雅降级（换小模型 / 缩短上下文 / 返回缓存）。

### 3.2 缓存：省钱的"复利"

缓存分两类，收益互补：

| 类型 | 原理 | 收益 |
|------|------|------|
| **响应缓存** | 相同输入直接返回历史结果 | 重复问题近乎零成本 |
| **Prompt 缓存** | 复用稳定的前缀（系统提示、知识库），命中后输入按折扣计价 | 长 system prompt 场景省 50%+ |

```python
"""响应缓存：LRU + 命中率统计（生产建议换 Redis）"""
from __future__ import annotations

import hashlib
from collections import OrderedDict


class ResponseCache:
    """基于 LRU 的响应缓存"""

    def __init__(self, max_size: int = 1000):
        self.max_size = max_size
        self._store: "OrderedDict[str, str]" = OrderedDict()
        self.hits = 0
        self.misses = 0

    @staticmethod
    def _key(prompt: str, model: str) -> str:
        return hashlib.sha256(f"{model}::{prompt}".encode("utf-8")).hexdigest()

    def get(self, prompt: str, model: str) -> str | None:
        key = self._key(prompt, model)
        if key in self._store:
            self._store.move_to_end(key)
            self.hits += 1
            return self._store[key]
        self.misses += 1
        return None

    def set(self, prompt: str, model: str, response: str) -> None:
        key = self._key(prompt, model)
        self._store[key] = response
        self._store.move_to_end(key)
        if len(self._store) > self.max_size:
            self._store.popitem(last=False)

    @property
    def hit_rate(self) -> float:
        total = self.hits + self.misses
        return self.hits / total if total else 0.0
```

**Prompt 缓存的正确姿势**——把**稳定内容放前面**，把**变化内容放后面**：

```python
# ✅ 好：稳定前缀（系统提示 + 知识库）在前，用户输入在后 → 易命中前缀缓存
messages = [
    {"role": "system", "content": STABLE_SYSTEM_PROMPT},   # 长期不变
    {"role": "user", "content": retrieved_context},        # 每次不同
    {"role": "user", "content": user_question},
]

# ❌ 差：把时间戳、随机 ID 放在最前面，前缀每次都变 → 缓存永不命中
```

> 📌 OpenAI 对 ≥1024 token 的稳定前缀**自动**启用缓存；Anthropic 需显式标记 `cache_control`。二者都会在响应中返回缓存命中的 token 数，可据此核算真实成本。

### 3.3 模型路由：好钢用在刀刃上

```python
"""模型路由：按任务复杂度选择模型"""
from __future__ import annotations

import os
import re

from langchain_openai import ChatOpenAI

SIMPLE_HINTS = ("你好", "谢谢", "翻译", "总结", "分类", "改写")
COMPLEX_HINTS = ("分析", "对比", "推理", "规划", "写代码", "生成报告")


def _llm(model: str, temperature: float = 0.2) -> ChatOpenAI:
    return ChatOpenAI(
        model=model,
        api_key=os.getenv("LLM_API_KEY") or os.getenv("OPENAI_API_KEY"),
        base_url=os.getenv("LLM_BASE_URL") or os.getenv("OPENAI_API_BASE"),
        temperature=temperature,
    )


class ModelRouter:
    """简单规则路由：可替换为分类器或小模型判别"""

    def __init__(self, cheap: str = "gpt-5-mini", strong: str | None = None):
        self.cheap_model = cheap
        self.strong_model = strong or os.getenv("LLM_MODEL_NAME", "gpt-5.5")

    def classify(self, task: str) -> str:
        """返回 simple / complex"""
        if any(h in task for h in SIMPLE_HINTS) and len(task) < 40:
            return "simple"
        if any(h in task for h in COMPLEX_HINTS):
            return "complex"
        return "simple" if len(task) < 20 else "complex"

    def pick(self, task: str) -> ChatOpenAI:
        """按复杂度返回对应模型客户端"""
        return _llm(self.cheap_model) if self.classify(task) == "simple" else _llm(self.strong_model)
```

> ⚠️ 规则路由够用即可；追求更准时，可训练一个**轻量分类器**，或用小模型先判复杂度。但要权衡：**多一次判别调用也是成本**。

### 3.4 限制输出与压缩上下文

```python
"""输出上限与上下文压缩：直接压降 token"""
from __future__ import annotations

from langchain_core.messages import BaseMessage

OUTPUT_LIMITS = {"concise": 120, "standard": 400, "detailed": 1000}


def trim_history(messages: list[BaseMessage], keep_last: int = 8) -> list[BaseMessage]:
    """只保留最近 N 条消息，防止历史无限膨胀"""
    return messages[-keep_last:]


def summarize_if_long(text: str, max_chars: int = 4000) -> str:
    """超长文本先截断（生产建议用 LLM 摘要替代截断）"""
    if len(text) <= max_chars:
        return text
    return text[:max_chars] + "\n…（内容已截断）"
```

> 💡 更彻底的做法是用 `SummarizationMiddleware`（见 [3.4 构建聊天 Agent](../03-LangChain实战/04-构建聊天Agent.md)）自动压缩长对话。

## 四、优化效果对比

| 策略 | 降低成本 | 实现难度 | 对质量影响 |
|------|---------|----------|-----------|
| **用更小模型** | 60–90% | ⭐ 低 | 简单任务几乎无影响 |
| **响应缓存** | 30–70% | ⭐⭐ 中 | 无（需处理时效性） |
| **Prompt 缓存** | 30–60% | ⭐ 低 | 无 |
| **上下文压缩** | 20–40% | ⭐⭐ 中 | 可能丢失细节 |
| **限制输出长度** | 10–30% | ⭐ 低 | 信息量减少 |
| **批量处理** | 10–20% | ⭐⭐⭐ 高 | 无（牺牲实时性） |

> 💡 **组合拳**：小模型路由 + 响应缓存 + Prompt 缓存 + 输出上限，通常能把成本压到原来的 **1/5 ~ 1/10**。

## 五、监控与告警

```python
"""成本告警：阈值触发，及时止损"""
from __future__ import annotations

from dataclasses import dataclass


@dataclass
class CostAlert:
    """成本告警器"""

    hourly_budget_usd: float = 10.0
    daily_budget_usd: float = 200.0

    def check(self, hourly_spend: float, daily_spend: float) -> list[dict]:
        alerts: list[dict] = []
        if hourly_spend > self.hourly_budget_usd:
            alerts.append(
                {"level": "warning", "message": f"小时成本 ${hourly_spend:.2f} 超预算"}
            )
        if daily_spend > self.daily_budget_usd:
            alerts.append(
                {"level": "critical", "message": f"日成本 ${daily_spend:.2f} 超预算，建议降级"}
            )
        return alerts
```

> 📌 把成本指标接入监控体系（见 [7.3 可观测性与监控](../07-生产部署/03-可观测性与监控.md)），在 Grafana 上按"租户 / 功能 / 模型"三个维度看板，并对超预算自动告警。
