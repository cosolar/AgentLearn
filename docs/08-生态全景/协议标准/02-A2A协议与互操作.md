# 8.11 A2A 协议与 Agent 互操作 —— 让 Agent 互相"打电话"

## 📖 本章目标

- 理解 A2A（Agent-to-Agent）协议要解决的问题
- 掌握 A2A 的核心概念：Agent Card、Task、Message、Artifact
- 理清 A2A 与 MCP 的分工
- 学会用 A2A 让不同框架、不同组织的 Agent 协同工作

> 📅 A2A v1.0 已 GA（2026 年），由 Google 发起、多家云厂商与平台共同支持。

---

## 一、为什么需要 A2A？

MCP 解决了"**Agent ↔ 工具**"的连接。但如果你的 Agent 需要调用**另一个 Agent**（可能是别的团队、别的公司、别的框架实现的），怎么办？

```text
问题：
  你的 LangGraph Agent  ──?──▶  合作方的 MAF Agent
  你的 OpenAI Agent      ──?──▶  SaaS 厂商的 Agent

没有 A2A：每个集成都是一对一的自定义对接
有 A2A：统一的"Agent 之间对话"协议
```

**A2A（Agent-to-Agent）** 用一个开放协议统一"**Agent ↔ Agent**"的协作：

| | MCP | A2A |
|--|-----|-----|
| 连接对象 | Agent ↔ **工具/数据** | Agent ↔ **Agent** |
| 解决的问题 | 能力接入 | 任务委派与协作 |
| 类比 | **USB-C**（接外设） | **HTTP**（跨系统通信） |
| 典型场景 | 让 Agent 会用 GitHub | 让客服 Agent 求助财务 Agent |

> 💡 **A2A 与 MCP 互补，不是竞争**：一个 Agent 既可以用 MCP 接工具，也可以用 A2A 找其他 Agent 帮忙。

---

## 二、核心概念

```text
┌──────────────┐                      ┌──────────────┐
│ Client Agent │ ──① 发现 Agent Card ─▶│ Remote Agent │
│  （发起方）   │ ──② 发送 Task ───────▶│  （执行方）   │
│              │ ◀──③ 返回 Artifact ───│              │
└──────────────┘    （支持流式/长时任务） └──────────────┘
```

| 概念 | 说明 |
|------|------|
| **Agent Card** | Agent 的"名片"（JSON），描述能力、技能、端点、鉴权方式 |
| **Task** | 一次委派的任务，有生命周期状态（submitted → working → completed/failed） |
| **Message** | 任务中的一次消息交换（含文本、文件、结构化数据） |
| **Artifact** | 任务的产出物（报告、文件、结构化结果） |
| **Streaming** | 通过 SSE 流式返回进度与中间结果 |

### 2.1 Agent Card 示例

```json
{
  "name": "research-agent",
  "description": "擅长联网研究并生成结构化报告",
  "url": "https://agents.example.com/research",
  "version": "1.0.0",
  "capabilities": {
    "streaming": true,
    "pushNotifications": true
  },
  "skills": [
    {
      "id": "web-research",
      "name": "联网研究",
      "description": "根据主题检索资料并输出报告",
      "inputModes": ["text/plain"],
      "outputModes": ["text/markdown"]
    }
  ],
  "securitySchemes": { "oauth2": { "...": "..." } }
}
```

> 📌 **发现机制**：客户端可通过约定路径（如 `/.well-known/agent-card.json`）获取 Agent Card，从而知道"这个 Agent 能做什么、怎么调用、要什么鉴权"。

## 三、一次完整的 A2A 协作流程

```text
① 发现      客户端 GET /.well-known/agent-card.json  → 拿到能力清单
② 委派      客户端 POST tasks/send  { message: "研究 2026 年 MCP 生态" }
③ 执行      远端 Agent 开始工作，状态流转：submitted → working
④ 流式进度  （可选）SSE 推送中间消息与状态
⑤ 产出      返回 Artifact：{ "report.md": "..." }
⑥ 完成      状态 → completed（或 failed / input-required）
```

若远端需要更多信息，会返回 `input-required`，客户端补充后再继续（类似 MCP 的 MRTR）。

---

## 四、A2A vs 传统函数调用

| 维度 | HTTP API 调用 | A2A |
|------|--------------|-----|
| 交互对象 | 无状态服务 | 有状态、可长时运行的 Agent |
| 任务粒度 | 单次请求/响应 | 完整任务生命周期 |
| 能力发现 | 需人工读接口文档 | Agent Card 自描述 |
| 流式/进度 | 需自行设计 | 协议原生支持 |
| 中间澄清 | 困难 | 原生 `input-required` |
| 跨组织 | 需大量对齐 | 统一协议 |

## 五、实战：让你的 Agent 成为一个 A2A Agent

以 **LangGraph + A2A** 为例（思路示意）：

```python
# server.py —— 把你的 LangGraph Agent 暴露为 A2A Agent
from langgraph.graph import StateGraph
from your_a2a_sdk import A2AServer, AgentCard, Task

graph = build_graph()   # 你的 LangGraph 工作流

card = AgentCard(
    name="report-agent",
    description="生成结构化研究报告",
    url="https://example.com/a2a/report",
    skills=[{"id": "report", "name": "报告生成"}],
)

server = A2AServer(agent_card=card)


@server.on_task
async def handle(task: Task) -> str:
    """收到 A2A 任务后，转成 LangGraph 输入执行"""
    user_text = task.messages[-1].text
    result = await graph.ainvoke({"messages": [{"role": "user", "content": user_text}]})
    return result["messages"][-1].content


server.run()
```

```python
# client.py —— 调用远端 A2A Agent
from your_a2a_sdk import A2AClient

client = A2AClient("https://example.com/a2a/report")
card = await client.get_agent_card()          # ① 发现
task = await client.send_task("研究 2026 年 MCP 生态")   # ② 委派

async for event in client.stream_task(task.id):  # ④ 流式进度
    print(event.status, event.message)

print(task.artifacts)                          # ⑤ 产出
```

> 💡 主流的 **Google ADK**、**Microsoft Agent Framework**、**LangGraph** 生态都已提供 A2A 集成；你也可以用官方 A2A SDK 自行对接任意框架。

## 六、典型应用场景

| 场景 | 说明 |
|------|------|
| **企业内跨团队 Agent 协作** | 客服 Agent 委派"退款审批"给财务 Agent |
| **跨组织协作** | 你的 Agent 调用合作方提供的专业 Agent |
| **SaaS Agent 市场** | 通过 Agent Card 发现并调用第三方 Agent 服务 |
| **混合框架系统** | LangGraph Agent ⇄ MAF Agent ⇄ 自研 Agent |
| **多 Agent 编排** | 主管 Agent 通过 A2A 分派子任务给多个专职 Agent |

## 七、A2A + MCP 组合拳

```text
一个典型的企业级 Agent 系统：

  用户
   │
   ▼
┌──────────────┐   A2A   ┌──────────────┐  A2A   ┌──────────────┐
│  客服 Agent  │────────▶│  财务 Agent  │───────▶│  风控 Agent  │
└──────┬───────┘         └──────┬───────┘        └──────┬───────┘
       │ MCP                    │ MCP                   │ MCP
       ▼                        ▼                       ▼
   知识库 MCP Server         ERP MCP Server          规则 MCP Server
```

- **A2A** 负责 Agent 之间的任务委派；
- **MCP** 负责每个 Agent 与各自工具的连接；
- 两者结合，系统**既可横向扩展（加 Agent），又可纵向扩展（加工具）**。
